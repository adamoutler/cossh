# User Story: SSH-191 - Sanitize Volatile PTY Read Buffers and Close Session Streams on Teardown

**As a Security-Conscious Terminal User and Android Systems Architect,**
I need all volatile PTY read buffers and active session streams to be explicitly zeroed out and safely closed upon session teardown, loop termination, or cancellation,
**so that** sensitive plaintext terminal data, credentials, and cryptographic artifacts cannot linger in mutable process heap memory or be leaked across subsequent sessions or process death serialization.

## Acceptance Criteria
1. **Volatile Buffer Sanitization in `PtyStreamBridge`:**
   - The internal read buffer (`ByteArray(4096)`) used in `PtyStreamBridge.startBridge()` is guaranteed to be overwritten with zeros (`buffer.fill(0)`) in a `finally` block when the bridge loop exits normally, encounters a stream exception, or is cancelled.
   - The buffer is configurable or accessible internally for thorough verification and zero-allocation testing.
2. **Session Stream Sanitization & Closure in `ActiveSessionState`:**
   - `ActiveSessionState` exposes a dedicated `fun sanitize()` method.
   - All buffered `ByteArray` output chunks remaining in `outputBuffer` are drained and zeroed out (`bytes.fill(0)`) within a synchronized block on `bufferLock`.
   - `ptyOutputStream` is safely closed and set to `null` within a protected try/catch block.
   - `sshShell` is set to `null` to eliminate dangling references to underlying remote shell channels.
3. **Session Teardown Integration in `SessionStreamRegistry`:**
   - `SessionStreamRegistry.clearSession(sessionId)` executes `session?.sanitize()` prior to transcript cleanup.
   - Clearing all sessions via `clearAllSessions()` propagates sanitization across all active sessions.
4. **Automated Verification & Zero-Warning Compliance:**
   - Unit tests in `SessionStreamRegistryTest` and `PtyStreamBridgeTest` comprehensively test normal stream processing, cancellation, exception handling, and memory zeroization.
   - The implementation compiles cleanly with zero compiler warnings and passes `lintDebug`.
