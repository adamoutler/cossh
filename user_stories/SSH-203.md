# User Story: SSH-203 - Biometric App Lock, Verification Token & State Machine

**As a security-conscious SSH terminal user,**
I want to lock CoSSH behind biometric authentication and configure an inactivity timeout,
**so that** unauthorized individuals cannot view my active connections, stored credentials, or execute commands if my device is unlocked or handed to someone else.

## Acceptance Criteria
1. **Cryptographic Key Initialization & CryptoObject Wrapping (`PasswordCipher`):**
   - Provide `initEncryptCipher(): Cipher` and `initDecryptCipher(iv: ByteArray): Cipher` using standard AES-GCM-NoPadding (256-bit key length, 128-bit authentication tag).
   - On Android P+ (API 28+), provide `wrapCryptoObject(cipher: Cipher): BiometricPrompt.CryptoObject`.
   - Maintain deterministic in-memory symmetric AES key reuse during unit test / headless / Robolectric environments (`resetFallbackKeyForTesting()` for test isolation).
2. **Secure Verification Token Storage & Lifecycle (`SecurityStorageManager`):**
   - `setupAppLock(cipher: Cipher)` generates 32 random bytes (`SecureRandom`), computes a SHA-256 fingerprint, encrypts the token with the authenticated cipher, and persists `app_lock_iv`, `app_lock_ciphertext`, and `app_lock_token_sha256` in EncryptedSharedPreferences (Base64 encoded). The raw 32-byte secret is wiped (`Arrays.fill(token, 0)`) in a `finally` block.
   - `verifyAppLockToken(cipher: Cipher): Boolean` safely parses stored Base64 payloads, decrypts the token with the authenticated cipher, verifies the SHA-256 hash using `MessageDigest.isEqual` (constant-time comparison), wipes the decrypted token array in `finally`, and returns `true` on match or `false` on any mismatch or decryption error.
   - Provide `getAppLockIv(): ByteArray?`, `isAppLockConfigured(): Boolean`, and `clearAppLock()`.
   - In `getAllProfiles()`, exclude `app_lock_*` prefixed keys to prevent key leakage into profile listings.
3. **User Preferences & Inactivity Timeout Configuration (`SettingsManager`):**
   - Provide persistent preferences `isAppLockEnabled: Boolean` (default `false`) and `appLockTimeoutSeconds: Int` (default `0` - immediately).
4. **App Lock State Machine & Lifecycle Tracking (`AppLockManager`):**
   - Manage observable state via `isLocked: StateFlow<Boolean>` and `pendingResumeIntent: MutableStateFlow<Intent?>`.
   - Support `enableAppLock(cipher: Cipher)`, `disableAppLock()`, `unlockWithCipher(cipher: Cipher)`, and `lock()`.
   - `onAppBackgrounded()`: immediately locks if `appLockTimeoutSeconds == 0`; otherwise records background timestamp.
   - `onAppForegrounded()`: checks elapsed time since backgrounding and transitions `isLocked = true` if elapsed time meets or exceeds `appLockTimeoutSeconds`.
   - Support custom clock injection (`() -> Long`) for deterministic testing.
5. **Interactive UI Configuration (`SettingsScreen` & `SettingsViewModel`):**
   - "App Security & Biometrics" card in Settings with toggle switch for App Lock and `ExposedDropdownMenuBox` for timeout options ("Immediately", "After 30 seconds", "After 1 minute", "After 5 minutes").
