# User Story: SSH-195 - Harden Host-Key Verification Prompting and Enforce Ephemeral Secret Zero-Wiping

**As an SSH user connecting to remote systems across untrusted and potentially hostile networks,**
I want CoSSH to strictly enforce Trust-On-First-Use (TOFU) host-key verification with prominent MITM change alerts, atomic `known_hosts` file updates, and guaranteed ephemeral secret destruction (zero-wiping all plaintext passwords, private key byte arrays, and form state upon connection success, failure, cancellation, or ViewModel clearance),
**so that** my credentials and SSH private keys are never exposed in JVM heap memory dumps and my connections are protected against active Man-in-the-Middle (MITM) host impersonation.

## Acceptance Criteria
1. **Host-Key Verification Hardening:**
   - In `TofuHostKeyVerifier`, identify matching host entries using robust host matching (`entry.appliesTo(formattedHost) || (port == 22 && entry.appliesTo(hostname))`), supporting standard ports (22), custom ports (`[host]:port`), and host aliases.
   - Accurately differentiate between first-time connections (`isKeyChanged == false`, expected fingerprint `null`) and key mismatch/replacement warnings (`isKeyChanged == true`, formatted with `SHA256:...` fingerprints for both expected and received keys).
   - Atomically overwrite changed keys in `known_hosts` using `Files.move(..., StandardCopyOption.ATOMIC_MOVE, StandardCopyOption.REPLACE_EXISTING)` without leaving duplicate or stale entries.
   - If the user aborts, cancels, or dismisses the host-key verification prompt, `verify()` must return `false`, leave `known_hosts` completely unmodified, and cause SSHJ/handshake to terminate with `TransportException(DisconnectReason.HOST_KEY_NOT_VERIFIABLE)`.
   - Prevent connection establishment and authentication whenever a host key is unverifiable or rejected.
2. **Guaranteed Ephemeral Secret Destruction (Zero-Wiping):**
   - In `SshHandshakeCoordinator.executeWithConnection`: execute `profile.clearSensitiveData()` in a mandatory `finally` block alongside `identity?.clearSensitiveData()`.
   - In `SshService.startSshConnection`: guarantee `profile?.clearSensitiveData()` is invoked in the service coroutine's `finally` block regardless of connection state (success, socket error, timeout, or cancellation).
   - In `SshConnectionManager.connectAndExecute`: wipe `profile.clearSensitiveData()` in `finally`.
   - In `IdentityViewModel.kt`: actively wipe `originalPassword?.fill(0)` and `privateKey?.fill(0)` in `resetState()` and override `onCleared() { resetState(); super.onCleared() }`.
   - In `IdentityViewModel.injectPublicKey`: wipe temporary credentials via `tempProfile.clearSensitiveData()` in a `finally` block.
   - In `AddEditProfileViewModel.kt`: zero-wipe `originalPassword?.fill(0)` in `resetState()` and override `onCleared() { resetState(); super.onCleared() }`.
   - In `UserPromptRegistry.kt`: implement `AutoCloseable` on `AuthCredentials` with `clear() { password?.fill('\u0000') }`.
