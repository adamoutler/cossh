# User Story: SSH-228 — OpenSSH User & Host Certificate Wire Parser, CA Signature Verification & Host-CA Wildcard Trust Store

## Epic
**SSH-188**: [EPIC] Security Differentiators — "Most Secure SSH Client on Android"

## User Story
**As a** security administrator and infrastructure engineer connecting to large-scale fleet or cloud environments,
**I need** CoSSH to parse and validate OpenSSH User and Host Certificates (following `PROTOCOL.certkeys`) and maintain a trusted Host-CA wildcard trust store with Zero-TOFU verification,
**So that** I can authenticate using CA-signed user certificates and connect to servers automatically without manual host-key confirmation prompts (Zero-TOFU) when signed by trusted Host CAs.

## Acceptance Criteria
1. **OpenSSH Certificate Data Models (`OpenSshCertificate.kt`):**
   - `OpenSshCertType` enum (`USER(1)`, `HOST(2)`).
   - `OpenSshCertificate` data class with full fields: `magic`, `nonce`, `subjectPublicKey`, `serial`, `certType`, `keyId`, `validPrincipals`, `validAfterSeconds`, `validBeforeSeconds`, `criticalOptions`, `extensions`, `caPublicKey`, `signatureAlgorithm`, `rawSignatureBlob`, and `signedBytes`.
   - `CertValidationResult` sealed interface (`Valid`, `Expired`, `NotYetValid`, `InvalidPrincipal`, `UnsupportedCriticalOption`, `InvalidSignature`, `InvalidCertType`, `CaNotTrusted`).
2. **Binary Wire Parser (`OpenSshCertificateParser.kt`):**
   - Wire parser following `PROTOCOL.certkeys` supporting Ed25519, RSA, and ECDSA certificates.
   - Helper methods `parse(encodedOrAuthorizedLine: String)`, `parseWireBytes(wireBytes: ByteArray)`, `serializeWireBytes(cert: OpenSshCertificate)`, and `encodeAuthorizedLine(cert: OpenSshCertificate)`.
3. **Cryptographic Certificate Validator (`OpenSshCertificateValidator.kt`):**
   - Validate temporal validity window against current epoch seconds.
   - Validate principal matching supporting exact and wildcard patterns (`*.internal.corp`), allowing any host if host certificate has empty principals.
   - Enforce Critical Options trap (reject any unknown critical options).
   - Validate CA cryptographic signature across Ed25519, RSA-SHA2-256/512, and ECDSA (RFC 5656 mpint r, s to ASN.1 DER conversion).
4. **SSHJ Certificate Key Provider (`CertificateKeyProvider.kt`):**
   - Bridge SSHJ `KeyProvider` returning the certificate public key (`com.hierynomus.sshj.userauth.certificate.Certificate`) and associated private key for `client.authPublickey()`.
5. **Wildcard Host-CA Trust Store (`KnownHostsManager.kt`):**
   - Support `@cert-authority` entries with wildcard host patterns (`*.internal.corp`, `!untrusted.corp,*.corp`).
   - Provide `findTrustedCaForHost(hostname, port): List<PublicKey>`.
   - Provide `saveCertAuthority(hostPattern, keyType, keyBlobBase64, comment)`.
   - Guarantee `hashAllPlaintextHosts()` preserves `@cert-authority` lines unhashed.
6. **Zero-TOFU Host Verification (`SshConnectionManager.kt`):**
   - In `TofuHostKeyVerifier`, check if server key is an OpenSSH Host Certificate signed by a trusted CA matching the host pattern; auto-accept without TOFU prompt (Zero-TOFU).
7. **UI Components (`SshCertificateBottomSheet.kt` & `KnownHostsScreen.kt`):**
   - `SshCertificateBottomSheet.kt` for viewing certificate details (type, serial, valid principals, temporal validity, CA fingerprint, critical options, extensions).
   - Host-CA filter chip in `KnownHostsScreen.kt` and `HOST-CA 🏛️` badge on HostKeyCard.
8. **Automated Unit Tests:**
   - 100% pass across `OpenSshCertificateParserTest.kt`, `OpenSshCertificateValidatorTest.kt`, and `HostCaTrustStoreTest.kt`.
9. **Zero-Tolerance Quality:**
   - Zero compiler warnings, strictly safe typing, no unhandled exceptions.
