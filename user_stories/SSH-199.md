# User Story: SSH-199 - Upgrade Backup Cryptography to Format v3 with 250k PBKDF2 Iterations, AAD Header Binding, and Full Backward Compatibility

**As a security-conscious CoSSH user archiving connection profiles and SSH private keys to persistent storage,**
I want backup exports encrypted using PBKDF2-HMAC-SHA256 with 250,000 iterations, 32-byte cryptographically secure salts, 12-byte IVs, and a self-describing binary header bound as Associated Authenticated Data (AAD) in AES-256-GCM, while maintaining 100% backward compatibility with legacy Format v2 archives and zero-wiping intermediate secrets,
**so that** offline brute-force attacks against exported backups are drastically harder to execute, backup metadata cannot be tampered with or swapped without cryptographic authentication failure, and legacy archives remain fully restorable.

## Acceptance Criteria
1. **PBKDF2 Hardening & Format v3 Export:**
   - Elevate key derivation workload to 250,000 PBKDF2WithHmacSHA256 iterations for all new export archives.
   - Use a 32-byte cryptographically random salt and 12-byte random IV.
   - Prepend self-describing Format v3 binary header: "COSSH" magic (5 bytes, ASCII), version 0x03 (1 byte), iteration count 250,000 big-endian Int (4 bytes), salt length 32 (1 byte), 32-byte salt, IV length 12 (1 byte), and 12-byte IV.
   - Bind the header as AES-256-GCM Associated Authenticated Data (AAD) via `cipher.updateAAD(header)` to ensure tamper-proof authentication of the archive metadata.
2. **Backward Compatibility with Format v2 Archives:**
   - When inspecting incoming backup data in `importProfilesFromZip`, verify whether the payload begins with the "COSSH" magic bytes.
   - If "COSSH" magic is absent, cleanly fall back to Format v2 archive unpacking: 65,536 iterations, 16-byte salt, 12-byte IV, and no AAD.
   - Support both full self-describing Format v3 (with 1-byte length headers) and compact Format v3 headers.
3. **Volatile State Sanitization (Zero-Wiping):**
   - Guarantee zero-wiping of intermediate plaintext byte arrays, derived secret key bytes, salt, and IV in mandatory `finally` blocks in both `exportProfilesToZip` and `importProfilesFromZip`.
   - Actively call `keySpec.clearPassword()` to scrub internal credential buffers.
