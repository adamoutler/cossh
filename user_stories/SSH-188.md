# User Story: SSH-188 — [EPIC] Security Differentiators — "Most Secure SSH Client on Android"

## Goal
Deliver hardened, enterprise-grade cryptographic security capabilities that establish CoSSH demonstrably as the "Most Secure SSH Client on Android":
1. **Hardware-Backed StrongBox Keys & Key Attestation**: Non-exportable EC key pairs generated inside dedicated StrongBox Keymaster/KeyMint hardware (Titan M2 / Secure Element) with ASN.1 X.509 key attestation verification (OID `1.3.6.1.4.1.11129.2.1.17`) and graceful multi-tier fallback to TEE Keystore on devices without StrongBox.
2. **OpenSSH Certificates & Host-CA Wildcard Trust**: Binary wire parser (`PROTOCOL.certkeys`) for Ed25519, RSA, and ECDSA certificates, temporal validity checks, OpenSSH critical options trap, CA signature verification, `@cert-authority` trust store with wildcard matching, and Zero-TOFU host authentication.
3. **OpenSSH Visual Host Key Randomart (Drunken Bishop) & High-Friction MITM Modal**: Pure Kotlin implementation of the authentic OpenSSH 17x9 drunken bishop algorithm (`" .o+=*BOX@%&#/^SE"`), high-contrast obsidian terminal rendering, side-by-side Expected vs Received key comparisons on key change, and a 2500ms `HoldToConfirmButton` with haptic feedback to prevent accidental TOFU MITM acceptance.
4. **Tamper-Evident SHA-256 Hash-Chained Security Audit Log**: Append-only audit logger with continuous SHA-256 hash chaining ($H_n = \text{SHA-256}(\text{CanonicalBytes}(R_n, H_{n-1}))$), hardware Keystore head anchoring in `EncryptedSharedPreferences`, POSIX `fsync` persistence via `FileChannel.force(true)`, and comprehensive tamper detection (payload mutation, sequence deletion, event reordering, and head rollback).

## Acceptance Criteria
1. **Full Security Suite Delivery**: All 4 constituent child tickets fully implemented, passing 100% of unit, integration, and UI snapshot tests.
2. **Cryptographic Hardening & Invariants**:
   - Zero-exportable private key protection: Private keys remain isolated within hardware chips (Titan M2 / ARM TrustZone) with `privateKey.encoded == null` safety.
   - Nonce-backed challenge verification rejecting replay attacks on key attestation certificates.
   - OpenSSH critical options trap: Rejection of any unrecognized critical option in user or host certificates.
   - Drunken bishop visual parity: Character-by-character parity against authentic OpenSSH `ssh-keygen -l -v` reference outputs.
   - Append-only hash chaining with deterministic canonical serialization and Keystore master-key head anchoring.
3. **Artifact-Backed Verification**:
   - Paparazzi UI screenshot artifacts committed under `docs/qa/` verifying all UI surfaces and security states.
   - Security whitepaper committed to `docs/security-whitepaper.md` detailing every security control, cryptographic specification, and verification proof.
   - Unit test suites passing cleanly with $\ge 80\%$ Jacoco instruction coverage, zero compiler warnings, and strictly safe typing.
