# User Story: SSH-183 — [EPIC] Cloud Sync Repair & Zero-Knowledge Sync v2

## Goal
Repair the paid Google Drive cloud sync feature, eliminating broken upload endpoints, auth race conditions, and infinite retry loops, and evolve the architecture into zero-knowledge sync v2:
1. Fix Google Drive v3 `appDataFolder` uploads using single-request multipart uploads (`uploadType=multipart`).
2. Implement silent background OAuth token acquisition in `DriveSyncManager` so `SyncWorker` can authenticate headlessly without prompt loops.
3. Eliminate billing entitlement race conditions by persisting verified entitlement states.
4. Implement end-to-end "Restore from Cloud" downloading and restoring encrypted profiles and identities.
5. Implement "Disable Cloud Sync" with optional remote Drive backup deletion and local passphrase scrubbing.
6. Enforce zero-knowledge `CharArray` passphrase storage and memory hygiene, preventing plaintext passphrases from lingering in the JVM heap.

## Child Tickets & Scope
- **SSH-205**: Fix Google Drive v3 appDataFolder Multipart Upload, SyncWorker Silent Auth, and Billing Entitlement Race (`Done`)
- **SSH-206**: Wire End-to-End Cloud Sync Restore, Disable Sync with Remote Purge, and Zero-Knowledge Passphrase Storage (`Done`)

## Acceptance Criteria
1. **Functional Cloud Sync & Restore**:
   - Backups created directly in `appDataFolder` via multipart upload.
   - End-to-end restore imports profiles and identities cleanly.
2. **Resilient Background Execution**:
   - `SyncWorker` executes silently and fails gracefully without infinite retry loops on 401/403.
   - Billing entitlement state checked reliably.
3. **Data Privacy & Zero Knowledge**:
   - Passphrase handled strictly in `CharArray` / `ByteArray` and zero-wiped after use.
   - User can disable sync and purge remote backups at any time.
4. **Artifact-Backed Verification**:
   - Paparazzi UI screenshots for Cloud Sync controls in `SettingsScreen`.
   - Comprehensive unit and integration test suites passing 100%.
