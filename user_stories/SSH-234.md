## Epic
**SSH-188**: [EPIC] Security Differentiators — "Most Secure SSH Client on Android"

## User Story
**As a** paranoiac Android security architect and enterprise infrastructure administrator,  
**I need** CoSSH to implement the post-quantum hybrid key exchange `sntrup761x25519-sha512@openssh.com` combining Streamlined NTRU Prime lattice cryptography with X25519 ECDH, and validate host keys against DNSSEC-authenticated RFC 4255 / RFC 8484 SSHFP resource records,  
**So that** my SSH sessions are protected against Harvest-Now-Decrypt-Later quantum decryption attacks, and initial host key authentication is cryptographically anchored via DNSSEC without Trust-On-First-Use (TOFU) vulnerability.

## Acceptance Criteria
1. **Post-Quantum Hybrid Key Exchange (`Sntrup761X25519KeyExchange.kt`):**
   - Implements OpenSSH `sntrup761x25519-sha512@openssh.com` combining BouncyCastle `sntrup761` (1158-byte public key, 1039-byte ciphertext) and `X25519` (32-byte public key, 32-byte shared secret).
   - Generates client ephemeral public key blob of exactly 1190 bytes (`sntrup761 || x25519`).
   - Parses server ephemeral public key blob of exactly 1071 bytes (`sntrup761_ciphertext || x25519`).
   - Computes combined shared secret $K = \text{SHA-512}(ss_{\text{sntrup761}} \parallel ss_{\text{x25519}})$ formatted as an SSH mpint.
   - Enforces volatile memory sanitization by strictly zero-wiping all ephemeral shared secret byte arrays in `finally` blocks.
   - Exposes `Sntrup761X25519KeyExchange.Factory` implementing `Factory.Named<KeyExchange>`.
2. **Cryptographic Suite Hardening (`SecureSshConfig.kt`):**
   - Registers `Sntrup761X25519KeyExchange.Factory()` at the head of `keyExchangeFactories` in `SecureSshConfig.kt`, ensuring quantum-resistant key exchange is negotiated with priority.
   - Preserves complete purge of deprecated/insecure algorithms (SHA-1, MD5, 3DES, Blowfish, DH Group 1).
3. **DNSSEC SSHFP Verification Engine (`SshfpVerifier.kt`):**
   - Implements RFC 8484 DNS wire query builder (`buildDnssecWireQuery`) for RR Type 44 (`SSHFP`) with EDNS0 OPT RR (Type 41) setting the `DO` (DNSSEC OK) bit (`0x8000`).
   - Implements binary DNS wire response parser (`parseDnsResponse`) extracting the `AD` (Authenticated Data) bit and SSHFP records.
   - Implements `verifyHostKeyWire` verifying raw host key bytes against authenticated SSHFP records:
     - Returns `DnssecNotAuthenticated` if the AD bit is false.
     - Returns `ValidDnssecMatch` when computed SHA-256 / SHA-1 host key fingerprint matches the authenticated record.
     - Returns `FingerprintMismatchAlert` with expected vs actual fingerprints upon mismatch.
     - Returns `NoRecordsFound` if no matching SSHFP records exist for the hostname and algorithm.
4. **Verification Proof & Unit Testing:**
   - 100% test pass in `Sntrup761X25519KeyExchangeTest.kt`, `SshfpVerifierTest.kt`, and `SecureSshConfigTest.kt`.
   - Comprehensive architectural documentation in Section 5 and Section 6 of `docs/security-whitepaper.md`.
   - Zero warnings, strictly safe typing, complete exception safety.
