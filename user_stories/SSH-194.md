# User Story: SSH-194 - Implement Terminal Bell Haptic Feedback and Shift Modifier State Tracking (readShiftKey)

**As an SSH terminal user,**
I want tactile haptic feedback when the terminal bell rings and accurate Shift key modifier state tracking (both physical and virtual),
**so that** I am immediately alerted to background events, command completion, and error rings without looking away, and can accurately type shifted terminal shortcuts and select text via standard terminal keybindings.

## Acceptance Criteria
1. **Terminal Bell Haptic Trigger:** When the terminal emulator receives an ASCII bell (`\u0007`), `TerminalViewModel.onBell` emits to `bellEvents: SharedFlow<Unit>`, and `TerminalScreen` collects this flow in `LaunchedEffect` to trigger `terminalViewRef.performHapticFeedback(HapticFeedbackConstants.KEYBOARD_TAP)`.
2. **Hardware Shift Detection:** `TerminalKeyMapper` tracks hardware Shift presses via `KeyEvent.isShiftPressed`, `KEYCODE_SHIFT_LEFT`, and `KEYCODE_SHIFT_RIGHT` in `onKeyDown`, resetting the state in `onKeyUp`.
3. **Virtual Shift Latching & Tri-State Modifiers:** `TerminalKeyMapper` manages virtual Shift state (`ModifierState.INACTIVE`, `STICKY`, `LOCKED`). In `STICKY` mode, the next keypress consumes the modifier and returns to `INACTIVE`. In `LOCKED` mode, the modifier persists across multiple keystrokes.
4. **Accurate `readShiftKey()` Query:** `TerminalKeyMapper.readShiftKey()` returns `true` if either hardware Shift is pressed or virtual Shift is active (`STICKY` or `LOCKED`), and `TerminalScreen` delegates `TerminalViewClient.readShiftKey()` directly to `TerminalKeyMapper.readShiftKey()`.
5. **Zero Main-Thread Latency & Clean Architecture:** All bell events flow through non-blocking shared flows with buffer capacity to prevent coroutine suspension on hot terminal output paths.
