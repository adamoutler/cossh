# User Story: SSH-264 — Make Window FLAG_SECURE and Obscured Touch Filtering Configurable (Default Off)

## User Story
*As a CoSSH user, I need screenshot blocking (`FLAG_SECURE`) and obscured touch filtering (`filterTouchesWhenObscured`) to be optional settings (defaulting to off) with dynamic runtime updates, while sensitive password, passphrase, and app lock screens continuously enforce `FLAG_SECURE` during display, so that I can capture terminal logs and use screen overlays without leaking credentials.*

---

## Technical Scope & Architecture

1. **Configurable Security Preferences in `SettingsManager`:**
   - Preference key `KEY_SCREENSHOT_BLOCKING_ENABLED` (`"is_screenshot_blocking_enabled"`, default `false`).
   - Preference key `KEY_OVERLAY_TOUCH_BLOCKING_ENABLED` (`"is_overlay_touch_blocking_enabled"`, default `false`).
   - Thread-safe SharedPreferences registration and unregistration hooks for real-time reactivity without application restarts.

2. **Dynamic Window Security in `MainActivity.kt`:**
   - In `onCreate()`, dynamically read `settingsManager.isScreenshotBlockingEnabled` and `settingsManager.isOverlayTouchBlockingEnabled` rather than unconditionally forcing both to active.
   - Register a `SharedPreferences.OnSharedPreferenceChangeListener` on `settingsManager` to immediately set or clear `WindowManager.LayoutParams.FLAG_SECURE` and toggle `window.decorView.filterTouchesWhenObscured` whenever user preferences change.
   - Cleanly unregister the preference change listener in `onDestroy()`.

3. **Credential and Authentication Screen Hardening:**
   - Sensitive credential entry modals (`PamAuthDialog`, `EncryptedKeyPassphraseModal`, `SyncPassphraseDialog`, `RestorePassphraseDialog`) and authentication views (`AppLockScreen`) utilize `DisposableEffect(view)` to:
     - Inspect parent window attributes for existing `FLAG_SECURE` state (`wasAlreadySecure`).
     - Actively add `WindowManager.LayoutParams.FLAG_SECURE` to ensure biometric prompt, PINs, and passphrases are strictly shielded from OS screen capture or recents previews.
     - On disposal, restore the parent window's prior security state (clearing `FLAG_SECURE` only if it was not already active prior to displaying the authentication interface).

4. **Automated Verification:**
   - Comprehensive unit test coverage in `PreReleaseCryptoAndAppLockHardeningTest` verifying:
     - Default `false` state for screenshot blocking and obscured touch blocking in `SettingsManager`.
     - SharedPreferences persistence of user preferences.
     - Dynamic application and clearing of `FLAG_SECURE` and `filterTouchesWhenObscured` in `MainActivity`.
     - `AppLockScreen` enforcing `FLAG_SECURE` during display and properly restoring prior window state upon disposal.

---

## Acceptance Criteria

1. **Default Off:** Screenshot blocking and obscured touch filtering are disabled by default (`false`) on clean installs.
2. **Dynamic Application:** Toggling screenshot blocking or overlay touch filtering takes effect immediately in `MainActivity` without requiring an app relaunch.
3. **AppLockScreen Shielding:** When biometric app lock is presented, `FLAG_SECURE` is active for the duration of the lock screen.
4. **State Preservation:** When dismissing `AppLockScreen` or sensitive passphrase dialogs, the window returns to non-secure if screenshot blocking was disabled, or remains secure if screenshot blocking was enabled by the user.
5. **No Regressions:** Targeted unit tests in `PreReleaseCryptoAndAppLockHardeningTest` pass cleanly.
