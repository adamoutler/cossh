# User Story: SSH-265 — Configurable Clipboard Auto-Clear, Sensitive Tagging, 60s App Lock Default & Audit Log Toggle

## User Story
**As a** systems administrator using CoSSH for routine terminal administration and secret management,
**I want** configurable clipboard auto-clear timeouts (Off by default, 30s, 60s, 5m), an optional Android 13+ sensitive clipboard tag toggle, a 60-second default app lock timeout, and an optional security audit log toggle,
**So that** routine clipboard copies and app switching do not disrupt my daily terminal workflow while retaining strict security controls when requested.

## Acceptance Criteria
1. **Configurable Clipboard Auto-Clear (`SecureClipboardManager.kt`, `SettingsManager.kt`):**
   - `SecureClipboardManager.copyToClipboard` defaults `autoClearDelayMs: Long? = null` and resolves `val effectiveDelayMs = autoClearDelayMs ?: (SettingsManager(context).clipboardAutoClearSeconds * 1000L)`.
   - When `effectiveDelayMs <= 0L` (e.g. default setting of `0s` / Off), clipboard auto-clear coroutine is skipped and any prior job is cancelled.
   - When configured to `> 0L` (e.g. 30s, 60s, 300s) or when `autoClearDelayMs` is explicitly supplied, coroutine schedules clipboard clearance after the delay if clipboard content matches.
2. **Android 13+ Sensitive Tagging Toggle (`SecureClipboardManager.kt`, `SettingsManager.kt`):**
   - On API 33+ (Tiramisu+), verify both `isSensitive` parameter and `SettingsManager(context).isClipboardSensitiveTaggingEnabled` (default `true`) before attaching `ClipDescription.EXTRA_IS_SENSITIVE = true` to primary clip extras.
   - When `isClipboardSensitiveTaggingEnabled == false` or `isSensitive == false`, sensitive extra tagging is omitted.
3. **App Lock Timeout Default Update (`SettingsManager.kt`):**
   - `DEFAULT_APP_LOCK_TIMEOUT_SECONDS` is set to `60` (1 minute), preventing disruptive immediate re-locking during brief app switching.
4. **Security Audit Log Toggle (`SecurityAuditLogManager.kt`, `SettingsManager.kt`):**
   - `SecurityAuditLogManager` checks `isAuditLogEnabled()` (`SettingsManager(context).enableSecurityAuditLog`, default `true`) prior to appending events.
   - When disabled, event persistence to disk (`audit_chain.jsonl`) and Keystore anchor persistence to `EncryptedSharedPreferences` are skipped, returning a safe no-op `AuditRecord`.
5. **Comprehensive Automated Verification (`SecureClipboardManagerTest.kt`, `SecurityAuditLogManagerTest.kt`):**
   - Unit tests verify default 0s auto-clear persistence past 30s/60s, configured 30s delay clearance, sensitive tagging toggle on/off, app lock default 60s, and audit logging persistence bypass when disabled.
   - Zero lint errors and zero compilation warnings.
