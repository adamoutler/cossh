# User Story: SSH-250 — Port Forwarding HTTP Tunneling Integration Tests

## Goal
As a security-focused systems engineer on CoSSH, I want comprehensive and deterministic automated integration test coverage verifying that Local (`-L`), Dynamic SOCKS5 (`-D`), and Remote (`-R`) port forwarding tunnels reliably transport HTTP/1.1 traffic across encrypted SSH channels, maintain byte-for-byte cryptographic integrity across large payloads, cleanly multiplex concurrent shell and tunnel streams without cross-talk, and aggressively clean up all client and server sockets upon termination.

## Acceptance Criteria
1. **Local Forwarding HTTP Tunneling (-L)**:
   - Configures `PortForwardConfig(PortForwardType.LOCAL, localPort, "127.0.0.1", httpServerPort)` via `PortForwardingOrchestrator.startPortForwards`.
   - Successfully tunnels HTTP `GET /status` requests to an embedded HTTP server, asserting HTTP `200 OK` and body `"status: ok"`.
   - Successfully tunnels large 32,768-byte deterministic ASCII payloads via HTTP `POST /echo`, asserting 100% byte-for-byte body integrity and matching `X-Payload-Sha256` header hash.
2. **Dynamic SOCKS5 HTTP Tunneling (-D)**:
   - Configures `PortForwardConfig(PortForwardType.DYNAMIC, socksPort, "", 0)` via `PortForwardingOrchestrator.startPortForwards`.
   - Complies with RFC 1928 SOCKS5 protocol negotiation (Version `0x05`, Auth `0x00`).
   - Supports IPv4 address resolution (`ATYP 0x01`, `127.0.0.1`) and Domain Name address resolution (`ATYP 0x03`, `localhost`), delivering both `GET /status` and `POST /echo` payloads with SHA-256 echo validation.
3. **Session Multiplexing & Stream Isolation**:
   - Opens an interactive SSH session shell (`startShell()`) concurrently on the same `SSHClient` connection alongside 4 simultaneous port-forwarded HTTP transfers (2 Local `-L` and 2 Dynamic `-D`).
   - Asserts zero stream cross-contamination: shell output contains only terminal echo tokens, and HTTP response streams contain exclusively valid HTTP status and payload bytes.
4. **Remote Reverse Forwarding & Socket Teardown (-R)**:
   - Configures `PortForwardConfig(PortForwardType.REMOTE, localHttpPort, "127.0.0.1", remoteBoundPort)`.
   - Verifies loopback binding on the SSH server and confirms reverse delivery of HTTP traffic to a local HTTP service.
   - Verifies `orchestrator.stopAll()` cleanly closes 100% of bound `localServerSockets` and all tracked `activeClientSockets`.
5. **Quality & Engineering Standards**:
   - Zero compiler warnings, zero lint errors, zero Detekt code smells.
   - Clean execution under Java 21 test runner.
