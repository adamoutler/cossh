# User Story: SSH-189 - Harden SSHJ Algorithm Suite via SecureSshConfig

**As an SSH terminal user operating over hostile network environments,**
I want CoSSH to enforce a hardened cryptographic algorithm suite that eliminates deprecated and vulnerable algorithms (specifically SHA-1, MD5, 3DES, Blowfish, and Diffie-Hellman Group 1),
**so that** my terminal sessions, credentials, and cryptographic exchanges are mathematically immune to Logjam, Sweet32, collision, and hash downgrade attacks.

## Acceptance Criteria
1. **Hostile Wire Hardened Configuration:** Implement `SecureSshConfig` extending `net.schmizz.sshj.AndroidConfig()`, proactively purging legacy algorithms upon initialization.
2. **Purge Obsolete Key Exchange:** All key exchange factories containing `sha1` or `group1-` (such as `diffie-hellman-group1-sha1`, `diffie-hellman-group14-sha1`) are stripped, eliminating vulnerability to the Logjam attack and weak 768/1024-bit discrete log groups.
3. **Purge Vulnerable Ciphers:** All cipher factories containing `3des` or `blowfish` (such as `3des-cbc`, `3des-ctr`, `blowfish-cbc`) are stripped, eliminating vulnerability to the Sweet32 64-bit block collision attack.
4. **Purge Compromised MACs:** All message authentication code (MAC) factories containing `sha1` or `md5` (such as `hmac-sha1`, `hmac-sha1-96`, `hmac-md5`, `hmac-md5-96`) are stripped, mitigating collision and hash downgrade vulnerabilities.
5. **Preserve Modern Cryptographic Suites:** Hardened configuration guarantees availability of modern algorithms:
   - Key Exchange: `curve25519-sha256`, `ecdh-sha2-nistp256`, `ecdh-sha2-nistp384`, `ecdh-sha2-nistp521`, `diffie-hellman-group14-sha256`, `diffie-hellman-group16-sha512`, `diffie-hellman-group18-sha512`.
   - Ciphers: `aes128-ctr`, `aes192-ctr`, `aes256-ctr`, `aes128-cbc`, `aes192-cbc`, `aes256-cbc`, `aes128-gcm@openssh.com`, `aes256-gcm@openssh.com`.
   - MACs: `hmac-sha2-256`, `hmac-sha2-512`, `hmac-sha2-256-etm@openssh.com`, `hmac-sha2-512-etm@openssh.com`.
6. **Universal Client Adoption:** Replace `net.schmizz.sshj.AndroidConfig()` with `SecureSshConfig()` in both `SshConnectionManager.kt` and `SshConnectionHandler.kt`.
