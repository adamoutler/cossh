# User Story: SSH-249 - Mock SSH Container Lockdown & Port Forwarding Hardening

**As a Paranoiac Android Security Architect,**
I need the Mock SSH container (`docker/mock-ssh/` and `mock-ssh` service) to be cryptographically hardened with thread-safe per-channel multiplexing, deterministic channel-kind dispatch, strict loopback HTTP-only port forwarding lockdowns, reverse-forwarding denial, socket timeouts, per-session concurrency semaphores, public key authentication, and dangerous environment variable filtering,
**so that** CoSSH integration tests run in an attack-resistant test environment that simulates realistic SSH/HTTP port forwarding while eliminating channel cross-talk race conditions and preventing container SSRF/RCE pivoting vectors.

---

## Acceptance Criteria

1. **Deterministic Channel Dispatch & Thread-Safety:**
   - In `MockServerInterface`, the scalar `last_channel_kind` is completely eliminated.
   - Channel metadata is managed via a thread-safe `self.channel_info = {}` dictionary keyed by `chanid`, protected by a dedicated `threading.Lock()` and backed by a fallback FIFO queue.
   - `check_channel_direct_tcpip_request` records `{ 'kind': 'direct-tcpip', 'origin': origin, 'destination': destination }` keyed by `chanid`.
   - `check_channel_request` records `{ 'kind': kind }` keyed by `chanid`.
   - `handle_connection` inspects `channel.get_id()` against `server.get_channel_info(chan_id)` to deterministically route `direct-tcpip` channels to `handle_direct_tcpip` and session channels to `handle_shell_channel`.

2. **Strict Port-Forwarding Lockdown:**
   - Port forwarding is restricted exclusively to loopback addresses (`ALLOWED_FORWARD_HOSTS = {'127.0.0.1', 'localhost'}`) and internal mock HTTP service (`INTERNAL_HTTP_PORT = int(os.environ.get('MOCK_HTTP_PORT', '32223'))`).
   - Requests to `0.0.0.0`, LAN IPs, cloud metadata endpoints (`169.254.169.254`), the container's SSH port (`2222`), Telnet port (`2323`), or any external host are strictly rejected with `paramiko.OPEN_FAILED_ADMINISTRATIVELY_PROHIBITED`.
   - Reverse port forwarding (`check_port_forward_request`) unconditionally returns `False`, rejecting all reverse tunnel requests.

3. **Public-Key Authentication & Safe Env Filtering:**
   - `MockServerInterface` advertises `password,publickey` via `get_allowed_auths`.
   - `check_auth_publickey` accepts authentication for the designated test user `testuser` while rejecting untrusted users.
   - `check_channel_env_request` inspects environment variable names, unconditionally rejecting dangerous variables (`LD_PRELOAD`, `LD_LIBRARY_PATH`, `BASH_ENV`, `ENV`, `IFS`, `SHELL`, `PATH`, `PYTHONPATH`, `PYTHONHOME`, or any key with prefix `LD_`).

4. **Forwarding Concurrency Bounds & Socket Timeouts:**
   - `handle_direct_tcpip` enforces a per-session concurrency semaphore (`MAX_CONCURRENT_FORWARDS_PER_SESSION = 8`).
   - Sockets and channels have strict `30.0s` read/write timeouts (`channel.settimeout(30.0)`, `dest_sock.settimeout(30.0)`).
   - `StatusHTTPRequestHandler` handles GET (`/status`, `/`, `/echo?q=...`) and POST (`/echo`, bounded to 64KB) returning content with `X-Payload-Sha256`.

5. **Automated Verification & Portability:**
   - `test_fuzz.py` verifies interactive prompt, long payload fuzzing with buffer truncation, allowed HTTP forward ping/echo, concurrent shell and HTTP multiplexing without cross-talk, adversarial destination rejection (`0.0.0.0`, `169.254.169.254`, SSH/Telnet ports, reverse forwards), and public key authentication.
   - Kotlin unit test `app/src/test/kotlin/com/adamoutler/ssh/network/MockSshContainerSecurityTest.kt` verifies repository file structure, security invariants in `server.py`, test coverage in `test_fuzz.py`, Docker configuration, and live subprocess execution.
