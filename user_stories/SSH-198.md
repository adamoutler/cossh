# User Story: SSH-198 - Enforce ≥80% Jacoco Coverage Verification, Remediate Sonar Exclusions, and Pin CI Workflows

**As a DevSecOps & Security Architect,**
I want the CI/CD pipeline to strictly enforce ≥80% Jacoco instruction coverage verification, remediate broad Sonar coverage exclusions across security-critical packages, and pin all GitHub/Forgejo Actions to immutable commit SHAs with least-privilege permissions,
**so that** malicious supply-chain tampering is blocked, CI runners cannot execute unauthorized repository writes, and untested regressions in cryptography, networking, synchronization, backup, and security are mathematically rejected before deployment.

## Acceptance Criteria
1. **Jacoco Coverage Verification Task**: Register `tasks.register<JacocoCoverageVerification>("jacocoTestCoverageVerification")` in `app/build.gradle.kts` enforcing a strict minimum of 80% (`minimum = 0.80.toBigDecimal()`) on the `INSTRUCTION` counter for the bundle.
2. **Sonar Coverage Exclusion Remediation**: Refactor `sonar.coverage.exclusions` in `app/build.gradle.kts` to completely remove all exclusions on core domain packages: `crypto`, `network`, `sync`, `backup`, and `security`. Exclusions are strictly constrained to UI Compose layers, generated files, and external SDK bridges.
3. **Instruction Coverage Deficit Remediation**:
   - `TelnetConnectionHandlerCoverageTest.kt` in `app/src/test/kotlin/com/adamoutler/ssh/network/` covering Telnet session lifecycle, options (`TerminalTypeOptionHandler`, `EchoOptionHandler`, `SuppressGAOptionHandler`), CR/LF translation in `autoFlushingStream`, streaming via `PtyStreamBridge`, and disconnect routines.
   - `DriveSyncAuthorizeCoverageTest.kt` in `app/src/test/kotlin/com/adamoutler/ssh/sync/` covering `DriveSyncManager.authorizeScope` resolution flows, direct token reception, `MainActivity.startAuthFlow`, `startIntentSenderForResult`, and failure branches using `ImmediateTask` simulation.
4. **Least-Privilege CI Permissions**: Restrict top-level workflow permissions in `.github/workflows/ci.yml` and `.forgejo/workflows/ci.yml` to `permissions: { contents: read }`, preventing compromised workflows from pushing or tampering with git refs.
5. **Immutable Supply-Chain Action Pinning**:
   - Pin `actions/checkout` to immutable commit SHA (`11bd71901bbe5b1630ceea73d27597364c9af683 # v4.2.2`).
   - Pin `actions/setup-java` to immutable commit SHA (`3a4f6e1af504cf6a31855fa899c6aa5355ba6c12 # v4.7.0`).
   - Pin `gradle/actions/setup-gradle` to immutable commit SHA (`748248ddd2a24f49513d8f472f81c3a07d4d50e1 # v4.4.4`).
   - Pin `actions/upload-artifact` in GitHub Actions to immutable commit SHA (`ea165f8d65b6e75b540449e92b4886f43607fa02 # v4.6.2`).
   - Pin `actions/upload-artifact` in Forgejo Actions to immutable v3 commit SHA (`a8a3f3ad30e3422c9c7b888a15615d19a852ae32 # v3.1.3`) preserving local Forgejo Twirp runner compatibility.
6. **Pipeline Verification Step**: Add `jacocoTestCoverageVerification` to the test execution step in both GitHub and Forgejo CI workflows.
