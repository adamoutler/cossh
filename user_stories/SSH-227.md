# User Story: SSH-227 — Hardware-Backed StrongBox Keys, Fallback Pipeline & X.509 Key Attestation Verification

## Epic
**SSH-188**: [EPIC] Security Differentiators — "Most Secure SSH Client on Android"

## User Story
**As a** security-conscious enterprise engineer or infrastructure operator,
**I need** CoSSH to generate hardware-backed private keys stored inside dedicated StrongBox Keymaster/KeyMint security chips (with automatic fallback to TEE and software Keystore), and cryptographically verify the X.509 ASN.1 Key Attestation certificate extension chain,
**So that** my SSH authentication keys cannot be extracted even by root-level or physical host compromises, and their hardware security level is provable with cryptographic attestation.

## Acceptance Criteria
1. **StrongBox Data Models (`KeyAttestationRecord.kt`):**
   - `AttestationSecurityLevel` enum: `SOFTWARE(0)`, `TRUSTED_ENVIRONMENT(1)`, `STRONGBOX(2)`, `UNKNOWN(-1)`.
   - `KeyAttestationRecord` data class containing attestation version, security level, keymaster version, keymaster security level, attestation challenge, and unique ID.
   - `StrongBoxKeyResult` data class containing alias, KeyPair, isStrongBoxBacked flag, attestation record, OpenSSH public key, and certificate chain.
2. **Hardware Key Pipeline & Fallback (`StrongBoxKeyManager.kt`):**
   - Feature detection via `context.packageManager.hasSystemFeature(PackageManager.FEATURE_STRONGBOX_KEYSTORE)`.
   - `generateStrongBoxKeyPair` supporting custom curves (`secp256r1`), optional user authentication, and custom challenge bytes.
   - Set `setIsStrongBoxBacked(true)` when supported; handle `StrongBoxUnavailableException` and Robolectric environments gracefully with fallback to standard Keystore TEE.
   - Parse ASN.1 Key Attestation extension OID `1.3.6.1.4.1.11129.2.1.17` using BouncyCastle to verify challenge and extract security levels.
3. **SSHJ Hardware Key Provider (`HardwareKeyProvider.kt`):**
   - Implement SSHJ `KeyProvider` bridging `PublicKey`, `PrivateKey` (`AndroidKeyStorePrivateKey`), and `KeyType.ECDSA256`.
   - Handle hardware non-exportable keys (`privateKey.encoded == null`) safely without errors.
4. **UI Components & Security Badges:**
   - `KeyAttestationBottomSheet.kt` for viewing hardware attestation levels, keymaster versions, and challenge digests.
   - Security tier badge (`StrongBox Hardware-Backed` 🛡️💎 vs `TEE Keystore` 🔒 vs `Imported Software Key` ⚠️) in `IdentityItem` on `IdentityListScreen.kt` and `AddEditIdentityScreen.kt`.
5. **Automated Unit Testing:**
   - 100% pass in `StrongBoxKeyManagerTest.kt` verifying feature detection, key generation fallback pipeline, synthetic ASN.1 attestation parsing (StrongBox, TEE, Software), challenge verification, and `HardwareKeyProvider` safe null-encoded handling.
6. **Zero-Tolerance Quality:**
   - Zero compiler warnings, strictly safe typing, no unhandled exceptions.
