# User Story: SSH-248 - Runtime Crypto & Protocol Wiring Hardening

**As a security-conscious SSH terminal user,**
I need cryptographic boundaries (DNSSEC SSHFP verification, HMAC automation intent validation, UTF-8 password sanitization, and hardened cipher negotiation) wired directly into the application's runtime pipeline,
**so that** host keys are authenticated against DNSSEC without MITM susceptibility, external automation intents cannot execute arbitrary commands without cryptographic authorization, multi-byte international passwords are never corrupted, and legacy CBC ciphers cannot expose session traffic to padding oracle attacks.

## Acceptance Criteria
1. **Live Intent Pipeline Wiring (`IntentSanitizer.kt` & `AppNavigation.kt`):**
   - `IntentSanitizer` supports `AutomationIntentGuard.ACTION_EXECUTE_AUTOMATION` with an optional `automationIntentGuard: AutomationIntentGuard? = null` parameter on `validateLaunchIntent` and `sanitizeAndNavigate`.
   - Rejects unverified automation intents if `automationIntentGuard == null`.
   - On `AutomationValidationResult.Authenticated`, confirms profile exists via predicate and matches `PROFILE_ID_REGEX` (`^[a-zA-Z0-9_-]{1,64}$`), returning a sanitized route.
   - Rejects forged, replayed, or expired automation intents with hostile extra keys.
   - `AppNavigation` remembers `AutomationIntentGuard` backed by `SecurityStorageManager` and `SecurityAuditLogManager` and supplies it to `sanitizeAndNavigate`.
2. **DNSSEC SSHFP Verification & SHA-256 Enforcement (`SshfpVerifier.kt` & `SshConnectionManager.kt`):**
   - `SshfpVerifier` strictly ignores/rejects legacy `FPTYPE_SHA1` records during verification, exclusively accepting `FPTYPE_SHA256` records to prevent SHA-1 collision attacks.
   - `TofuHostKeyVerifier` wires an optional `sshfpVerifier: SshfpVerifier? = null` parameter.
   - When an unknown host key is encountered (`status == HostKeyStatus.UNKNOWN`), verifies the host key against DNSSEC records via `sshfpVerifier.verifyHostKey(hostname, key.algorithm, key.encoded)`:
     - On `SshfpVerificationResult.Verified`: auto-accepts and persists host key via `knownHostsManager.saveHostKey(hostname, port, key)`, logs audit event, and returns `true` without interactive prompt.
     - On `SshfpVerificationResult.FingerprintMismatchAlert`: logs rejection to `auditLogManager` and returns `false` immediately without prompting.
     - On `NoRecordsFound`, `DnssecNotAuthenticated`, or `NetworkError`: falls through cleanly to the standard interactive TOFU prompt.
3. **UTF-8 Multi-Byte Password Decoding (`PasswordAuthenticator.kt`):**
   - Replaces byte-to-char conversion with `decodeUtf8BytesToChars(bytes: ByteArray): CharArray` using `StandardCharsets.UTF_8.newDecoder()`, `ByteBuffer.wrap(bytes)`, and `CharBuffer`.
   - Correctly preserves multi-byte international characters (e.g., `"pässwörd🔒€"`).
   - Zero-wipes the intermediate `CharBuffer` backing array in a `finally` block to preserve the Volatile State Sanitization invariant.
4. **Purge Legacy `-cbc` Ciphers from SSH Transport (`SecureSshConfig.kt`):**
   - Filters out any cipher factory containing `"cbc"` in addition to `"3des"` and `"blowfish"`.
   - Retains modern AEAD and CTR ciphers (e.g., `aes128-ctr`, `aes256-ctr`, `aes128-gcm@openssh.com`, `aes256-gcm@openssh.com`).
5. **Comprehensive Automated Verification:**
   - Unit tests in `RuntimeCryptoWiringAndSuiteHardeningTest.kt` verifying all 5 security capabilities.
   - Zero compiler warnings, zero detekt code smells, and passes all existing regression tests.
