# User Story: SSH-209 - Isolated Multi-Hop Jump Host (ProxyJump) Architecture

**As an infrastructure engineer administering servers in private subnets,**
I want CoSSH to route SSH sessions through intermediate jump hosts (bastions) with direct-tcpip channel forwarding and loop prevention,
**so that** I can securely access isolated backend machines without exposing target ports to the public Internet or storing private keys on the bastion.

## Acceptance Criteria
1. **Configurable ProxyJump Configuration (`ConnectionProfile` & `AddEditProfileScreen`):**
   - Provide a Jump Host selector allowing the user to select an existing SSH profile as a proxy bastion.
   - Filter candidate profiles to exclude non-SSH protocols and exclude the profile being edited.
2. **Deterministic DAG Cycle Detection (`JumpHostGraphValidator` & `JumpHostSelector`):**
   - Implement cycle detection algorithm `hasJumpHostCycle(currentProfileId, selectedJumpHostId, profiles)`.
   - Prevent selecting any profile that would form a direct or transitive routing cycle (e.g., A ➔ B ➔ A or A ➔ B ➔ C ➔ A), rendering warning badges and disabling invalid options.
3. **Encrypted Route Breadcrumb Visualization (`JumpHostSelector`):**
   - Display a visual route preview card (`Device ➔ Bastion ➔ Target Host:Port`) informing the user of the end-to-end encrypted direct-tcpip tunnel route.
4. **Native Direct-TCPIP Tunnel Chaining (`ConnectionProtocolFactory` & `SshConnectionHandler`):**
   - Establish native SSH direct-tcpip channel using `jumpClient.newDirectConnection(targetHost, targetPort)`.
   - Connect target `SSHClient` via the direct connection tunnel (`targetClient.connectVia(tunnel)`).
   - Ensure clean cascaded teardown: closing target connection cleanly closes the proxy tunnel and disconnects the jump client without leaking socket descriptors.
5. **Zero-Tolerance Quality:**
   - Zero warnings, no unhandled exceptions, strictly safe typing, comprehensive test suite.
