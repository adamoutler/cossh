# User Story: SSH-196 - Harden External Intent and Deep-Link Handling via IntentSanitizer

**As a Security-Conscious Mobile Terminal User and Android Systems Architect,**
I need all incoming intents and resume triggers destined for terminal sessions to be rigorously validated and sanitized through `IntentSanitizer`,
**so that** hostile external applications cannot inject malicious routes, trigger unauthorized session navigation, spoof active sessions, or replay stale intent extras across activity recreations.

## Acceptance Criteria
1. **Strict Intent Action Verification:**
   - The intent action must strictly match `com.adamoutler.ssh.RESUME_$sessionId`.
   - Intents with generic actions (e.g., `ACTION_MAIN`, `ACTION_VIEW`), mismatched session identifiers, or missing actions must be rejected.
2. **Whitelist Regex Format Validation:**
   - Both `profileId` and `sessionId` extras must strictly conform to regex `^[a-zA-Z0-9_-]{1,64}$`.
   - Malformed strings containing spaces, delimiters (`&`, `?`, `=`, `;`), slashes, path traversal sequences, or excessive lengths (>64 chars) are immediately rejected.
3. **Active Memory Session Lookup:**
   - The `sessionId` must exist in `ConnectionStateRepository.sessions`. Non-existent or expired sessions are rejected.
4. **Encrypted Storage Profile Validation:**
   - The `profileId` must resolve to an authentic, saved profile via `SecurityStorageManager.getProfile(profileId) != null`. Unstored or forged profile IDs are rejected.
5. **Route URI Encoding:**
   - Deep-link navigation routes must encode query arguments (`"terminal?profileId=${Uri.encode(profileId)}&sessionId=${Uri.encode(sessionId)}"`) to prevent route parameter injection.
6. **Replay Attack Prevention:**
   - Processed resume intents must immediately clear the host activity's intent (`activity.intent = Intent()`) to prevent automated replay during configuration changes or activity recreation.
7. **Graceful Navigation Exception Handling:**
   - Calls to `navController.navigate` must be protected by a `try/catch` block to handle unexpected navigation framework exceptions without crashing the application.
8. **Automated Verification & Zero-Warning Compliance:**
   - Complete unit test coverage in `IntentSanitizerTest.kt` (14 comprehensive test cases) and `AppNavigationCoverageTest.kt` (12 test cases).
   - Zero compiler warnings, zero lint errors (`lintDebug` passes cleanly).
