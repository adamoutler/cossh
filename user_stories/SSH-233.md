# User Story: SSH-233 — Fix TerminalRenderer NullPointerException by Enforcing TerminalView Initialization Order

## Goal
Prevent crash when launching the terminal screen by enforcing the correct initialization order on Termux's `TerminalView` and wrapping typeface configuration in defensive exception guards.

## Problem Statement
When transitioning to `TerminalScreen`, `AndroidView` factory in `TerminalScreen.kt` invoked:
```kotlin
terminalView.setTypeface(resolvedFont.getTypeface())
terminalView.setTextSize(...)
```
In `com.termux.view.TerminalView`, `setTypeface(Typeface)` creates a new `TerminalRenderer(this.mRenderer.mTextSize, typeface)`. Because `mRenderer` is only instantiated inside `setTextSize()`, calling `setTypeface()` first resulted in a fatal `java.lang.NullPointerException: Attempt to read from field 'int com.termux.view.TerminalRenderer.mTextSize' on a null object reference`.

## Acceptance Criteria
1. **Enforce Initialization Order**: In `TerminalScreen.kt` AndroidView factory, invoke `terminalView.setTextSize()` before `terminalView.setTypeface()` so `TerminalRenderer` is guaranteed to be instantiated before typeface configuration.
2. **Defensive Error Handling**: Wrap `terminalView.setTypeface()` in try-catch to safely fallback to system monospace and log diagnostics via `AppLog.w` without crashing the application.
3. **Automated Unit Tests**: Add unit test in `TerminalViewInitializationTest.kt` verifying initialization order and defensive error handling.
4. **Physical Verification**: Confirm zero new crashes in `/data/user/0/com.adamoutler.cobaltssh.debug/files/secure_crashes/` on device.
5. **Zero-Tolerance Quality**: Zero compiler warnings, strictly safe typing, and zero unhandled exceptions.
