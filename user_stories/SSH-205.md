# User Story: SSH-205 - Google Drive v3 Multipart Upload, Silent Token Refresh & Billing Entitlement Persistence

**As a CoSSH user with a Google Drive sync entitlement,**
I want reliable, resilient background backups to my private Google Drive appDataFolder with atomic multipart file uploads, media PATCH updates, silent token refresh, and persistent billing state,
**so that** my connection profiles and identities stay safely synced across devices without 404 upload errors, false entitlement rejections, or runaway retry loops on auth failures.

## Acceptance Criteria
1. **Single-Step RFC 2387 Multipart Upload:** `DriveSyncManager` uses `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart` with `multipart/related` boundary, `application/json` metadata (`{"name": "cossh_backup.enc", "parents": ["appDataFolder"]}`), and `application/octet-stream` binary payload when creating backups in `appDataFolder`, eliminating the fragile two-step root upload + move failure mode.
2. **Media PATCH for Updates:** `DriveSyncManager` updates existing remote backup files via `PATCH https://www.googleapis.com/upload/drive/v3/files/$fileId?uploadType=media`.
3. **Single Encryption & Backward Compatibility:** `DriveSyncManager` eliminates redundant double-encryption on upload, and transparently detects ZIP magic header (`PK\x03\x04` / `0x50, 0x4B, 0x03, 0x04`) on download to support both modern single-encrypted payloads and legacy double-encrypted backups.
4. **Silent Token Refresh & Caching:** `DriveSyncManager` caches the OAuth access token in companion state (`cachedOAuthToken`) and provides `getOrRefreshAccessToken()` using `Identity.getAuthorizationClient` for background workers.
5. **Remote Backup Deletion:** `DriveSyncManager.deleteBackup()` locates and issues HTTP DELETE to `https://www.googleapis.com/drive/v3/files/$fileId`, returning `true` for success (200..299 or 404).
6. **Billing Entitlement Persistence & Async Barrier:** `BillingManager` persists entitlement in `BillingPrefs` (`cloud_sync_entitled`) upon purchase or query, and exposes `awaitCloudSyncEntitlement()` barrier with a 5-second timeout so `SyncWorker` does not read a premature `false` before `BillingClient` establishes connection.
7. **SyncWorker Resilience & Error Classification:** `SyncWorker` checks `settingsManager.isCloudSyncActive` and `billingManager.awaitCloudSyncEntitlement()`. Permanent failures (HTTP 401, 403, unauthenticated, null passphrase) return `Result.failure()` immediately without retry. Transient network errors retry only when `runAttemptCount < 3`, preventing infinite retry thrashing.
