# User Story: SSH-216 — Implement Dedicated Known Hosts Management Screen & OpenSSH Hashed Hosts Parity

## Story
As a systems administrator connecting to multiple environments,
I want a dedicated Known Hosts management screen under Settings to inspect saved host keys, verify fingerprints, and selectively delete obsolete entries,
while supporting OpenSSH hashed known-hosts format (`|1|...`) to protect my network topology from host-enumeration attacks, with atomic file writes preventing file corruption.

## Acceptance Criteria
1. **Known Hosts Management Core (`KnownHostsManager.kt`):**
   - Parse and serialize entries from `filesDir/ssh_known_hosts`.
   - Support both plaintext and OpenSSH hashed host entries (`|1|<salt_b64>|<hash_b64>`).
   - Fix `TofuHostKeyVerifier` replacement logic: accurately match and replace existing hashed entries using HMAC-SHA1 comparison.
   - Provide one-touch "Hash All Plaintext Hosts" action to migrate plaintext entries to hashed format.
   - Enforce atomic file replacement using temporary files and `Files.move(..., ATOMIC_MOVE, REPLACE_EXISTING)` with standard replacement fallback under thread-safe synchronization.
2. **Dedicated Known Hosts UI (`KnownHostsScreen.kt` & `KnownHostsViewModel.kt`):**
   - Accessible from App Settings ("Security & Trust" / "App Security & Biometrics" section).
   - Display search/filter query field matching hostname, IP, port, or fingerprint.
   - Algorithm Filter Chips: `All`, `Ed25519`, `RSA`, `ECDSA`.
   - Host Key Card displaying host pattern/badge, algorithm chip, SHA-256 fingerprint, and one-touch copy button (with 30s clipboard auto-clear).
   - Deletion support: single entry delete confirmation dialog and multi-select bulk deletion with safety confirmation.
3. **Zero-Tolerance Quality:**
   - Zero compiler warnings, strictly safe typing, no unhandled exceptions.
   - Comprehensive unit and Paparazzi screenshot test coverage.
