# User Story: SSH-257 — Volatile Credential Sanitization & Async Identity Save Race Fix

## Goal
Enforce uncompromising volatile state sanitization and eliminate concurrency race conditions across profile persistence, identity management, and backup import/export workflows, ensuring zero cleartext credentials linger in memory even under exceptional failure modes.

---

## Security Threat Models & Mitigations

1. **Memory Scraping & Heap Dump Leakage:**
   - *Threat:* Passwords, passphrases, and private key byte arrays remaining allocated on the JVM heap following save operations, vulnerable to memory inspection, OS-level crash dump extraction, or process serialization leaks.
   - *Mitigation:* Unconditional `try ... finally` sanitization calling `clearSensitiveData()` (which explicitly executes `.fill(0)`) on all `ConnectionProfile` and `IdentityProfile` instances across ViewModels and backup managers.

2. **Asynchronous UI State Reset Race Condition:**
   - *Threat:* In `AddEditIdentityScreen`, invoking `viewModel.resetState()` on the main thread immediately after `viewModel.saveIdentity(identity)` caused `resetState()` to zero out `uiState.privateKey` and `originalPassword` while the background coroutine in `IdentityViewModel` was still reading and serializing the byte array, resulting in blank or corrupted private keys written to storage.
   - *Mitigation:* `AddEditIdentityScreen` passes independent defensive copies (`passBytes?.copyOf()`, `uiState.privateKey?.copyOf()`) to `IdentityProfile`. Main-thread state zeroing cannot mutate the copy in transit, and `IdentityViewModel` scrubs the defensive copy once persistence concludes.

3. **Fault-Path Credential Abandonment:**
   - *Threat:* Exceptions during storage persistence (e.g., Keystore hardware faults, disk full errors, corrupted zip archives) skipping cleanup routines and leaving decrypted credentials in memory.
   - *Mitigation:* Defensive `try ... finally` and `try ... catch` wrappers in `AddEditProfileViewModel`, `IdentityViewModel`, `BackupManager`, and `BackupCryptoManager` ensure byte buffers are actively zeroed even when exceptions abort the operation.

---

## Technical Implementation Details

- **`AddEditProfileViewModel.kt`:**
  - In `saveProfileFromState(id)` and `saveProfile(...)`, wrapped `storageManager.saveProfile(profile)` in a `try ... finally` block invoking `profile.clearSensitiveData()` and `resetState()`.
- **`AddEditIdentityScreen.kt` & `IdentityViewModel.kt`:**
  - In `AddEditIdentityScreen.kt`, passed `password = passBytes?.copyOf()` and `privateKey = uiState.privateKey?.copyOf()` into `IdentityProfile(...)`.
  - In `IdentityViewModel.kt`, wrapped `storageManager.saveIdentity(identityToSave)` in a `try ... finally` block that invokes `identityToSave.clearSensitiveData()` and `identity.clearSensitiveData()`.
- **`BackupManager.kt` & `BackupCryptoManager.kt`:**
  - In `BackupManager.kt`, wrapped hydrated profile/identity lists in `exportBackup()` and `importBackup()` within `try ... finally` blocks that invoke `.forEach { it.clearSensitiveData() }`.
  - In `BackupCryptoManager.kt`, added `try ... catch` cleanup in `importProfilesFromZip()` ensuring decoded profile and identity secrets are zeroed if an error occurs post-Base64 decoding, while preserving the caller's `password: CharArray`.
- **`VolatileStateLifecycleSanitizationTest.kt`:**
  - Automated tests validating all failure and success cleanup paths.

---

## Acceptance Criteria

1. **ViewModel Zero-Wipe:**
   - `AddEditProfileViewModel` zeroes `password` and resets state regardless of whether `storageManager.saveProfile` succeeds or throws.
2. **Identity Save Isolation:**
   - `AddEditIdentityScreen`'s defensive copies prevent main thread `resetState()` from zeroing out private keys being persisted in background coroutines.
   - `IdentityViewModel` scrubs `IdentityProfile` secrets in `finally`.
3. **Backup Lifecycle Sanitization:**
   - `BackupManager.exportBackup()` and `importBackup()` wipe all hydrated profile and identity credentials in memory upon completion or error.
   - `BackupCryptoManager.importProfilesFromZip()` cleans up decoded byte buffers if deserialization fails, leaving caller's password intact.
4. **Automated Verification:**
   - 100% test pass rate in `VolatileStateLifecycleSanitizationTest`.
