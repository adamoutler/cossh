# User Story: SSH-239 — Adaptive Display Architecture & Extra Keys Row Integration

## Goal
Enable CoSSH to intelligently partition terminal and control viewports across form factors (compact phones, medium dual-pane tablets, expanded desktop / Samsung DeX / ChromeOS, and foldable tabletop / book postures), automatically toggle virtual extra keys rows based on hardware keyboard detection (except in tabletop posture where the bottom pane acts as a touch control deck), and integrate selectable extra keys presets with TalkBack accessibility semantics.

## Background & Problem Statement
1. **Form Factor Diversity**: Modern Android devices range from compact portrait smartphones (< 600dp), dual-pane tablet viewports (600dp..840dp), expanded desktop windowing environments (>= 840dp, Samsung DeX, ChromeOS), to foldable hardware featuring physical hinges. Terminal applications must adapt dynamically to display geometry without clipping or occluded panes.
2. **Foldable Posture Specialization**: Foldable devices in tabletop posture (`HALF_OPENED` horizontal hinge) provide an ergonomic partition: the upper display pane presents the terminal canvas while the lower display pane hosts virtual extra keys and touch input controls. In book posture (`HALF_OPENED` or separating vertical hinge), side-by-side terminal / session split panes avoid the physical hinge crease.
3. **Hardware Keyboard Detection & Virtual Extra Keys**: When an external physical keyboard is attached or in desktop windowing environments, virtual extra keys consume vertical terminal canvas unnecessarily. They should automatically collapse unless the device is in tabletop posture.
4. **Preset Selection & Accessibility Integration**: Operators need their selected extra keys preset (`DEFAULT`, `VIM_CODING`, `TMUX`, `NAVIGATION`) persisted in `SettingsManager`, rendered dynamically on Page 0 of `TerminalExtraKeys`, dispatched accurately via `TerminalKeyMapper`, and fully readable by TalkBack screen readers via Compose accessibility semantics.

- **`app/src/main/kotlin/com/adamoutler/ssh/ui/layout/AdaptiveLayoutResolver.kt`**:
  - `AdaptiveLayoutMode`: `SINGLE_PANE_COMPACT`, `DUAL_PANE_MEDIUM`, `EXPANDED_DESKTOP_DEX`, `TABLETOP_HALF_OPEN`, `BOOK_POSTURE_SPLIT`.
  - `HingeOrientation`: `HORIZONTAL`, `VERTICAL`.
  - `HingePostureState`: `HALF_OPENED`, `FLAT`, `CLOSED`.
  - `HingeOcclusionType`: `NONE`, `FULL`.
  - `HingeBoundsDp`, `FoldingFeatureInfo`, `DeviceEnvironmentInfo`, `LayoutRectDp`, `AdaptiveLayoutState`.
  - `AdaptiveLayoutResolver.resolveMode(...)` and `resolveLayout(...)` implementing responsive thresholding and hinge partition math.
- **`app/src/main/kotlin/com/adamoutler/ssh/crypto/SettingsManager.kt`**:
  - `globalExtraKeysPreset`: Persisted preference string (`KEY_GLOBAL_EXTRA_KEYS_PRESET`).
  - `extraKeysPreset`: Typed property accessing `ExtraKeysPresetId` with safe fallback to `ExtraKeysPresetId.DEFAULT`.
- **`app/src/main/kotlin/com/adamoutler/ssh/ui/components/TerminalExtraKeys.kt`**:
  - Optional parameters `presetId: ExtraKeysPresetId = ExtraKeysPresetId.DEFAULT` and `onKeySpecPress: ((ExtraKeySpec) -> Unit)? = null` preserving backward compatibility.
  - Page 0 renders structured rows from `ExtraKeysPresets.getPreset(presetId)`.
  - `ExtraKeyButton` adds accessibility `semantics { this.contentDescription = contentDescription ?: text }`.
- **`app/src/main/kotlin/com/adamoutler/ssh/ui/components/TerminalKeyMapper.kt`**:
  - `onKeySpecPress(spec: ExtraKeySpec)` dispatching modifier toggle or payload/ANSI bytes to terminal with sticky modifier consumption.
  - `onExtraKeyPress` fallback to UTF-8 bytes for custom characters not covered by static ANSI map.
- **Unit & Integration Test Suites**:

  - `app/src/test/kotlin/com/adamoutler/ssh/ui/components/ExtraKeysPresetIntegrationTest.kt`: 5 tests covering SettingsManager persistence, mapper UTF-8 fallbacks, modifier toggling, and Compose UI TalkBack content descriptions.

## Acceptance Criteria
1. **Adaptive Layout Calculation**:
   - Foldable in `HALF_OPENED` horizontal hinge or separating horizontal hinge resolves to `TABLETOP_HALF_OPEN`. Primary pane covers upper display; secondary pane covers lower display.
   - Foldable in `HALF_OPENED` vertical hinge or separating vertical hinge resolves to `BOOK_POSTURE_SPLIT`. Primary pane covers left; secondary covers right.
   - DeX mode, ChromeOS, or display width >= 840dp resolves to `EXPANDED_DESKTOP_DEX`.
   - Display width between 600dp and 840dp resolves to `DUAL_PANE_MEDIUM`.
   - Compact display (< 600dp) resolves to `SINGLE_PANE_COMPACT`.
2. **Virtual Extra Keys Visibility**:
   - `shouldShowVirtualExtraKeys` is `false` when `hasHardwareKeyboard == true`, except in `TABLETOP_HALF_OPEN` where it is always `true`.
3. **Settings Persistence**:
   - `SettingsManager.extraKeysPreset` defaults to `DEFAULT`, stores chosen preset, and safely falls back to `DEFAULT` if preferences contain unknown strings.
4. **Extra Keys Row UI & Key Dispatching**:
   - `TerminalExtraKeys` renders keys for the active preset on Page 0.
   - Key buttons declare accessibility content descriptions matching `ExtraKeySpec.contentDescription`.
   - `TerminalKeyMapper.onKeySpecPress` toggles modifier keys and dispatches payload or ANSI bytes.
   - `TerminalKeyMapper.onExtraKeyPress` falls back to raw UTF-8 bytes for custom keys.
5. **Quality & Engineering Standards**:
   - Zero compiler warnings, zero Detekt lint issues.
   - All tests pass locally and in CI/CD pipeline.
