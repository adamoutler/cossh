# User Story: SSH-190 - Scrub DriveSync PII Logging and Enforce IME Incognito / No-Personalized-Learning Flags

**As a security and privacy-conscious SSH user,**
I need my Google Account identity excluded from system logs and my sensitive inputs (passwords and private keys) isolated from predictive soft keyboard learning,
**so that** shoulder surfers, logcat consumers, and third-party keyboard telemetry cannot harvest my email address, connection passwords, or private key material.

## Acceptance Criteria
1. **Scrub DriveSync PII Logging:** In `DriveSyncManager.kt`, sanitize OAuth / Google ID Token logging so that `googleIdTokenCredential.id` (email / user account ID) is never printed to stdout/logcat, emitting only `DriveSyncManager: Auth successful`.
2. **IME Incognito & No Personalized Learning on Passwords:** In `SecurePasswordEditText.kt`, enforce `(imeOptions and EditorInfo.IME_FLAG_NO_PERSONALIZED_LEARNING) != 0` and `privateImeOptions = "incognito"` in both initial/masked and visible/unmasked states across both `factory` and `update` blocks.
3. **Private Key Input Protection:** In `AddEditIdentityScreen.kt`, enforce `keyboardOptions = KeyboardOptions(autoCorrect = false, keyboardType = KeyboardType.Password)` on the manual PEM private key input field to prevent third-party keyboards from learning or caching cryptographic key material in their suggestion dictionaries.
4. **Automated Unit Testing & Zero Regression:**
   - Robolectric test in `SecurePasswordEditTextTest.kt` verifying `IME_FLAG_NO_PERSONALIZED_LEARNING` and `privateImeOptions == "incognito"` across state toggling.
   - PII logging test in `DriveSyncManagerPiiLogTest.kt` verifying source and stdout output never emit `Auth successful for:` or email patterns.
   - Zero warnings, zero errors in local unit tests and lint.
