# User Story: SSH-180 — [EPIC] Security Hardening — audit findings & release blockers

## Goal
Eliminate every Critical/High finding from the comprehensive October 2026 threat-model audit and resolve the Medium/Low architectural findings, making the "most secure SSH client on Android" claim defensible:
1. Harden SSHJ transport cryptography by disabling broken legacy ciphers (3DES, Blowfish), weak MACs (MD5, SHA-1), and weak KEX algorithms via `SecureSshConfig`.
2. Protect user privacy by stripping Google account PII from sync logs and enforcing `IME_FLAG_NO_PERSONALIZED_LEARNING` / incognito on all sensitive credential fields.
3. Sanitize volatile memory: zero-wipe PTY read buffers, session streams, intermediate passphrases, and unencrypted keys in `finally` blocks.
4. Harden TOFU host-key verification with `HoldToConfirmButton` (1500ms safety hold) on fingerprint changes and atomic `ssh_known_hosts` file updates.
5. Elevate backup cryptography to Format v3 with 250,000 PBKDF2 iterations and authenticated AAD headers while maintaining 100% legacy v2 restore compatibility.
6. Harden port-forwarding listeners with a 32-connection cap and 15s handshake timeouts; auto-wipe copied sensitive terminal text from clipboard after 30 seconds.
7. Route all production logging through `AppLog`, scrub crash logs of secrets, and prevent BouncyCastle from preempting Android's native hardware-accelerated Conscrypt TLS provider.

## Acceptance Criteria
1. **Zero High/Critical Audit Findings Remaining**: All 7 child tickets fully completed and certified by `reality-checker`.
2. **Volatile Memory Sanitization**: Plaintext credentials, passphrases, and session buffers must be zero-wiped immediately after use.
3. **Defense-in-Depth Protections**: Cryptographic downgrade protection, atomic known_hosts writes, sensitive clipboard auto-clearing, and non-blocking SOCKS connection caps.
4. **Artifact-Backed Verification**:
   - Comprehensive unit test suites verifying all cryptographic primitives, sanitizers, and listeners.
   - Zero compiler warnings, strictly safe typing, and zero unhandled exceptions.
