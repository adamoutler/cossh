# User Story: SSH-178 - Optimize Gboard and Soft Keyboard Paste Performance via Micro-Batching

**As an SSH terminal user using soft keyboards (e.g. Gboard),**
I need smooth, instantaneous paste and rapid typing throughput without main thread stutter,
**so that** multi-line scripts, URLs, and large paste buffers transmit efficiently without flooding system logs or stalling the PTY stream.

## Acceptance Criteria
1. **Micro-Batch Channel Draining:** Implement a testable channel drainer/consumer (`TerminalWriteBatcher.processChannel`) for `writeChannel` in `TerminalScreen.kt` that awaits the first byte array, drains all immediately available queued chunks via `tryReceive().getOrNull()` up to a 64KB safe cap, writes them to `ptyOutputStream`, and invokes `ptyOutputStream.flush()` once per drained batch.
2. **Eliminate Hot-Path Logging IPC:** Remove synchronous `println` calls from `onCodePoint`, `onKeyDown`, and `sendToTerminal` in `TerminalKeyMapper.kt` and `TerminalScreen.kt` to eliminate blocking Android logd IPC overhead on every keystroke.
3. **Sub-10ms Single Keystroke Latency:** Ensure single keystrokes suspend normally without any timer or artificial delay, flushing immediately with low latency (<20ms).
4. **Coalesced Micro-Batching Verification:** Rapidly queuing 1,000 single-character byte arrays into `writeChannel` results in >95% reduction in `flush()` invocations with 100% data integrity and preserved character ordering.
5. **Benchmark Verification:** Compare unbatched vs batched write+flush over 1,000 characters against a simulated slow-flush stream, proving >= 10x reduction in flush count and write duration.
