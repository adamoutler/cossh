# User Story: SSH-270 — Fix Clipboard Copy Default, Paced Terminal Paste Input Buffer & KnownHostsViewModel Instantiation Crash

## Goal
Ensure seamless terminal clipboard operations and stable navigation by enabling clipboard copying by default, buffering and pacing paste data transfers to prevent remote terminal and PTY resets, and annotating `KnownHostsViewModel` with `@JvmOverloads` so Android ViewModel reflection instantiates cleanly when opening Known Hosts from Settings.

---

## Technical Details & Architecture

1. **Known Hosts Reflection Instantiation Fix (`KnownHostsViewModel`)**:
   - `KnownHostsViewModel` extends `AndroidViewModel(application)`. When instantiated dynamically via Jetpack Compose's `viewModel()` without a custom factory in `AppNavigation.kt` (`composable("knownHosts")`), Android's `AndroidViewModelFactory` uses Java reflection looking for a constructor matching `(Application.class)`.
   - Without `@JvmOverloads`, Kotlin only emitted `(Application, KnownHostsManager)` in bytecode, throwing `NoSuchMethodException: com.adamoutler.ssh.ui.screens.KnownHostsViewModel.<init>(android.app.Application)` and crashing the app upon navigation from `SettingsScreen`.
   - Adding `@JvmOverloads constructor(...)` generates both the two-parameter constructor and the single-parameter `(Application)` constructor in Java bytecode, resolving the crash cleanly.

2. **Clipboard Copy Default Enablement**:
   - Terminal clipboard copy was previously blocked by default because `KEY_ALLOW_OSC52_CLIPBOARD` defaulted to `false` in `SettingsManager` and `allowOsc52Clipboard` was tied strictly to `isRobolectric` in `TerminalViewModel`.
   - In `SettingsManager`, `DEFAULT_ALLOW_OSC52_CLIPBOARD` is now set to `true`.
   - In `TerminalViewModel`, `var allowOsc52Clipboard: Boolean = true` by default and `getBoolean("allow_osc52_clipboard", true)` is used as fallback.
   - In `SettingsViewModel` and `SettingsScreen`, default UI states reflect `allowOsc52Clipboard = true`.

3. **Paced Terminal Paste Input Buffering**:
   - Long-press paste into the terminal was previously streaming the entire clipboard byte buffer in a single unbuffered burst to `ptyOutputStream.write(bytes); ptyOutputStream.flush()`.
   - For multi-line text or fast bursts, this burst exceeded the remote PTY/SSH window capacity, corrupting line discipline or triggering remote shell disconnection, resulting in terminal resets.
   - `onPasteTextFromClipboard` now splits payloads into bounded 256-byte micro-chunks, writing and flushing each chunk within `synchronized(ptyOutputStream)` and inserting a non-blocking `delay(10L)` between chunks.
   - Single small pastes execute instantly with 0ms delay, while larger pastes are paced reliably without dropping characters or overwhelming the SSH stream.

---

## Acceptance Criteria

1. **Known Hosts Navigation**:
   - `ViewModelProvider.AndroidViewModelFactory.getInstance(application).create(KnownHostsViewModel::class.java)` executes cleanly without throwing `NoSuchMethodException`.
   - Navigating from Settings to Known Hosts opens `KnownHostsScreen` without crashing.

2. **Clipboard Copy Out of the Box**:
   - Terminal text selection and copy commands write to the Android system `ClipboardManager` by default without requiring manual user toggle in Settings.
   - `SettingsManager.allowOsc52Clipboard` defaults to `true`.

3. **Paste Buffering & Pacing**:
   - Large or multi-line pastes are processed in 256-byte micro-chunks with paced delays.
   - PTY output streams are flushed per chunk and never overrun the remote terminal line discipline.
