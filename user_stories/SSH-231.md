# User Story: SSH-231 — Implement Multi-Factor Authentication Pipeline & SSH_AUTH_PARTIAL Continuation Engine

## User Story
**As a security-conscious administrator connecting to hardened SSH infrastructure (such as mock.hackedyour.info),**  
**I need** CoSSH to smoothly process multi-step authentication (`SSH_AUTH_PARTIAL` / `SSH_MSG_USERAUTH_FAILURE` with `partial_success = true`) and prompt sequentially for required secondary credentials (e.g. public key followed by password or 2FA OTP / keyboard-interactive),  
**So that** multi-factor authentication succeeds without stalling, disconnecting, or throwing unhandled `UserAuthException`s.

---

## Acceptance Criteria
1. **Multi-Factor State Detection:** Inspect `sshClient.userAuth.hadPartialSuccess()` in `SshHandshakeCoordinator.kt` and `CompositeAuthenticator` when primary authentication partially succeeds.
2. **Sequential Auth Orchestration:** Query remaining allowed methods via `sshClient.userAuth.allowedMethods` and trigger secondary authentication (`MultiFactorContinuationEngine.kt`) on the live transport without resetting the connection.
3. **Interactive Multi-Prompt Registration:** Update `UserPromptRegistry.kt`, `TerminalDialogs.kt`, and `PamAuthDialog.kt` to handle sequential prompts with clear step indicators (`[Step 2/2: Second Factor Required]`, `completedFactor` badge).
4. **Unit Tests:** Add comprehensive unit tests in `MultiFactorAuthenticationTest.kt` verifying partial auth continuation for publickey+password and publickey+keyboard-interactive combinations.
5. **Zero-Tolerance Quality:** Zero compiler warnings, strictly safe typing, and zero unhandled exceptions.

---

## Technical Details
- **RFC 4252 §5.1 Compliance:** When the SSH server returns `SSH_MSG_USERAUTH_FAILURE` with `partial_success = true`, SSHJ flags `userAuth.hadPartialSuccess() = true` and updates `userAuth.allowedMethods`.
- **`MultiFactorContinuationEngine`:** Coordinates secondary authenticators (`KeyboardInteractiveAuthenticator`, `PasswordAuthenticator`) sequentially over the established transport.
- **Volatile Memory Sanitization:** All password and challenge-response buffers (`CharArray` and `ByteArray`) are zeroed in `finally` blocks immediately upon dispatch.
