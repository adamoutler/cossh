# User Story: SSH-254 — Enforce Entitlement Integrity on Startup, Provision AndroidKeyStore HMAC Key, and Eliminate Dead DriveSync PBKDF2 Ciphers

## Epic
**SSH-188**: [EPIC] Security Differentiators — "Most Secure SSH Client on Android"  
**SSH-180**: [EPIC] Security Hardening

## User Story
**As a** security architect hardening CoSSH's cryptographic entitlement and backup pipelines,  
**I need** `BillingManager` to enforce `verifyEntitlementIntegrity()` during startup so tampered `BillingPrefs.xml` entries are immediately rejected and purged, replace the hardcoded plaintext `HMAC_KEY_SEED` with an `AndroidKeyStore`-backed `HmacSHA256` secret key (with a deterministic in-memory fallback for Robolectric JVM unit tests), and eliminate dead 65,536-iteration `encrypt`/`decrypt` methods in `DriveSyncManager.kt`,  
**So that** adversaries modifying shared preferences on rooted devices cannot unlock Cloud Sync features without valid cryptographic proof, HMAC secret material is protected inside the hardware Keystore rather than extracted from static binary constants, and `BackupCryptoManager`'s 250,000-iteration v3 AAD cipher remains the single unambiguous encryption authority across the entire cloud backup subsystem.

## Acceptance Criteria
1. **Startup Entitlement Tamper Enforcement (`BillingManager.kt`):**
   - Initialize `_isCloudSyncEnabled` with `isTestOverrideAllowed() || verifyEntitlementIntegrity()`.
   - In `verifyEntitlementIntegrity()`, if `cloud_sync_entitled = true` is found in `BillingPrefs.xml` but the HMAC tag is missing or invalid, `BillingManager` MUST immediately reset `cloud_sync_entitled` to `false`, purge `cloud_sync_entitled_hmac` from `BillingPrefs.xml`, and return `false`.
   - A tampered `BillingPrefs.xml` file MUST NOT enable `isCloudSyncEnabled.value` under any condition when `forceCloudSyncEnabledForTest` is `false`.
2. **AndroidKeyStore-Backed Entitlement HMAC Key (`BillingManager.kt`):**
   - Completely remove the static plaintext `HMAC_KEY_SEED = "CoSSH_Billing_Entitlement_Key_Salt_2026"` constant.
   - Provision and load an `HmacSHA256` secret key inside `AndroidKeyStore` (`KEY_ALGORITHM_HMAC_SHA256`, alias `"cossh_billing_entitlement_hmac_key"`, `KeyProperties.PURPOSE_SIGN`).
   - Implement a deterministic in-memory `SecretKey` fallback when running under Robolectric/JVM test runners to guarantee stable, reproducible test execution.
3. **Elimination of Dead 65,536-Iteration Ciphers (`DriveSyncManager.kt` & `sync/GEMINI.md`):**
   - Delete dead `private fun encrypt(...)` and `private fun decrypt(...)` methods in `DriveSyncManager.kt`.
   - In `downloadBackup()`, remove the obsolete fallback to `decrypt()` and return `downloadedPayload` directly on HTTP 200..299.
   - Remove dead companion iteration properties (`DEFAULT_PBKDF2_ITERATIONS`, `pbkdf2Iterations`, `setIterationsForTesting`, `resetIterationsForTesting`) and clean up all unused crypto imports.
   - Update `app/src/main/kotlin/com/adamoutler/ssh/sync/GEMINI.md` documenting `DriveSyncManager` as a pure transport layer with `BackupCryptoManager` as the sole encryption authority.
4. **Test Suite Alignment & Regression Coverage:**
   - Update `PreReleasePrivacyAndOsLeakageTest.kt` asserting startup rejection, state flow deactivation, and preference sanitization of tampered or missing HMAC tags.
   - Update `BillingEntitlementPersistenceTest.kt` to persist valid HMAC tags during cache tests and assert purge behavior on tampered preferences.
   - Clean up `DriveSyncManagerTest.kt` and `DriveSyncMultipartTest.kt` by removing reflection-based tests against deleted `encrypt`/`decrypt` methods.
