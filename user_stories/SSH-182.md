# User Story: SSH-182 — [EPIC] Optional App Lock & Authentication (incl. intent hardening)

## Goal
Provide a cryptographically hardened, optional App Lock feature backed by Android Keystore auth-bound AES-256-GCM keys and `BiometricPrompt.CryptoObject` (never a boolean flag check) with configurable re-lock timeouts, paired with strict intent sanitization and biometric gating for deep-links and sensitive command snippets:
1. Validate and sanitize all external Intent extras (`profile_id`, `session_id`) via `IntentSanitizer`, rejecting traversal tokens and URL-encoding navigation arguments.
2. Implement `AppLockCipher` and `AppLockManager` to maintain cryptographic lock state, holding background timeout thresholds and requiring genuine `cipher.doFinal()` execution to unlock.
3. Gate `MainActivity` and `AppNavigation` behind `AppLockScreen` when enabled, buffering deep-links in `pendingResumeIntent` until biometric authentication succeeds.
4. Enforce `BiometricPrompt` authentication before dispatching command snippets marked `requireAuth = true` to the terminal PTY stream.

- **SSH-203**: Implement Hardware-Backed AppLockCipher (CryptoObject), AppLockManager, and Settings App Lock UI (`Done`)

## Acceptance Criteria
1. **Cryptographic App Lock Engine**:
   - Zero reliance on easily spoofed boolean memory flags; unlocks require genuine AES-GCM decryption via Keystore `CryptoObject`.
   - Configurable timeout options (Immediately, 30s, 60s, 300s).
2. **Intent Sanitization & Deep-Link Gating**:
   - External intents must strictly match allowlisted notification resume patterns.
   - External intents never execute while the app is locked; buffered in `pendingResumeIntent`.
3. **Sensitive Snippet Protection**:
   - Snippets with `requireAuth = true` require biometric prompt verification prior to PTY execution.
4. **Artifact-Backed Verification**:
   - Paparazzi UI screenshots for `AppLockScreen` and Settings App Lock card.
   - Unit and Robolectric test suites passing with 100% success.
