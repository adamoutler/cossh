# User Story: SSH-201 - Production Logging Migration, TLS Provider Precedence, Network Security Cleartext Ban & Crash Redaction

**As a systems security engineer maintaining enterprise-grade Android client integrity,**
I want CoSSH to route all system logs through `AppLog` rather than standard out, register the BouncyCastle security provider at position 2 without preempting Android's native Conscrypt TLS provider at position 1, enforce a global ban on cleartext network traffic with removal of dummy pins, redact Bearer tokens and passwords from crash reports, and prune crash logs to at most 5 files,
**so that** production log streams do not leak diagnostic information, native TLS certificate validation is preserved, cleartext HTTP transmissions are blocked at the Android OS network security config layer, and on-device crash logs never expose authentication tokens or exhaust disk space.

## Acceptance Criteria
1. **Production Logging Migration (`AppLog`):**
   - Eliminate all raw `println` calls across production classes: `PortForwardingOrchestrator.kt`, `TelnetConnectionHandler.kt`, `SecureCrashHandler.kt`, `MainActivity.kt`, `DriveSyncManager.kt`, and `TerminalViewModel.kt`.
   - Route all diagnostic, warning, and error outputs through `AppLog.v`, `AppLog.d`, `AppLog.i`, `AppLog.w`, or `AppLog.e`.
2. **Security Provider Precedence:**
   - In `CoSshApplication.kt`, register `BouncyCastleProvider` at position 2 (`Security.insertProviderAt(BouncyCastleProvider(), 2)`).
   - Ensure Android's native platform TLS provider (Conscrypt/AndroidOpenSSL) at position 1 is preserved and not superseded during SSL/TLS handshakes.
   - Update `CoSshApplicationTest.kt` and create `ProviderPrecedenceTest.kt`.
3. **Network Security Configuration:**
   - In `app/src/main/res/xml/network_security_config.xml`, eliminate the dummy `example.com` pin-set with hardcoded SHA-256 hashes.
   - Enforce `<base-config cleartextTrafficPermitted="false" />` to reject all unencrypted cleartext HTTP traffic across the application.
4. **Crash Handler Scrubbing & Log Pruning:**
   - In `SecureCrashHandler.kt`, expand redaction regexes to scrub Bearer/OAuth authorization tokens (`[REDACTED_TOKEN]`), access/refresh tokens (`[REDACTED_TOKEN]`), and password/passwd/pwd parameter assignments (`[REDACTED_PASSWORD]`).
   - Implement automatic crash log retention pruning (`pruneOldCrashLogs`) in the internal files directory, deleting older files to retain at most 5 files (`MAX_CRASH_LOGS = 5`).
