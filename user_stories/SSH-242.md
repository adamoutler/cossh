# User Story: SSH-242 — Pre-Release Crypto Hardening, Hardware Keystore Wiring & AppLock Immunity

## Epic
**SSH-188**: [EPIC] Security Differentiators — "Most Secure SSH Client on Android"

## User Story
**As a** paranoiac Android security architect,  
**I need** CoSSH to eliminate biometric authentication failure bypasses, preserve window-level `FLAG_SECURE` screen masking across all modal dialog and bottom sheet lifecycles, and wire StrongBox / TEE hardware-backed Keystore keys end-to-end through storage, UI state, and SSH connection handshakes,  
**So that** adversaries cannot bypass app-lock through exception inducement or headless execution, terminal screen buffers are never exposed to recent-apps preview capture or screenshotting when dismissable modals close, and hardware-isolated private keys (where key material is non-exportable) are fully usable for authenticating production SSH sessions.

## Acceptance Criteria
1. **Biometric App-Lock Exception Bypass Elimination (`MainActivity.kt` & `AppLockManager.kt`):**
   - In `AppLockManager`, introduce `var allowHeadlessTestFallback: Boolean = false` defaulting strictly to `false`.
   - In `MainActivity.promptBiometricUnlock()`, catch blocks handling `BiometricPrompt` service unavailability or initialization exceptions must log the error via `AppLog.e` and refuse to unlock unless `allowHeadlessTestFallback` is explicitly `true`.
   - Production execution guarantees the application remains locked upon biometric hardware failure or prompt exceptions.
2. **Preserve Window-Level `FLAG_SECURE` Across Dialog Disposals (`PamAuthDialog.kt`, `EncryptedKeyPassphraseModal.kt`, `UrlConfirmationBottomSheet.kt`, `KeyManagementScreen.kt`):**
   - In `DisposableEffect` blocks, check `val wasAlreadySecure = ((window?.attributes?.flags ?: 0) and WindowManager.LayoutParams.FLAG_SECURE) != 0` prior to setting `FLAG_SECURE`.
   - In `onDispose`, only clear `FLAG_SECURE` if `!wasAlreadySecure`.
   - Guarantees that when `MainActivity` or parent activities enforce window-level `FLAG_SECURE`, dismissing child dialogs, modals, or bottom sheets does not strip `FLAG_SECURE` from the main terminal activity.
3. **End-to-End StrongBox / TEE Hardware Keystore Keys (`IdentityProfile.kt`, `IdentityStorageManager.kt`, `IdentityViewModel.kt`, `SshHandshakeCoordinator.kt`):**
   - Add `val keystoreAlias: String? = null` to `IdentityProfile` with updated serialization, `equals`, and `hashCode`.
   - In `IdentityStorageManager`, persist and retrieve `keystoreAlias` in both JSON metadata and dedicated `${id}_keystore_alias` entries, while ensuring `getAllIdentities()` filters auxiliary entries and hydrates aliases with backward compatibility.
   - In `IdentityViewModel`, propagate `keystoreAlias` from `StrongBoxKeyManager.generateStrongBoxKeyPair()` into `uiState` and preserve `keystoreAlias` when persisting identities through `saveIdentity()`.
   - In `SshHandshakeCoordinator`, implement `HardwareKeyAuthenticator(keyProvider: KeyProvider)` and `resolveHardwareKeyProvider(alias, publicKeyStr)`. When `identity.keystoreAlias != null`, dynamically resolve the hardware-backed key from `AndroidKeyStore` (or `testHardwareKeyProviders`) and register `HardwareKeyAuthenticator` for SSH authentication.
4. **Comprehensive Automated Verification (`PreReleaseCryptoAndAppLockHardeningTest.kt`):**
   - Full test coverage validating biometric exception lockout, window `FLAG_SECURE` preservation, `IdentityProfile` serialization, `IdentityStorageManager` CRUD and migration, `SshHandshakeCoordinator` authenticator resolution, and `IdentityViewModel` state integration.
5. **Zero-Tolerance Quality:**
   - 0 compiler warnings, 0 unhandled exceptions, strictly safe typing, complete cryptographic boundary enforcement.
