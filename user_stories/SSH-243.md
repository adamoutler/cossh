# User Story: SSH-243 — Protocol, Terminal & Input Boundary Hardening

## Epic
**SSH-187**: [EPIC] Power Features — SFTP, Mosh, Automation, Accessibility

## User Story
**As a** security-conscious terminal user connecting to remote servers and importing configuration backups,
**I want** strict sanitization of initial directories, remote OSC 52 clipboard gating, bracketed paste hardening, bounded detached session output queues, PBKDF2 iteration bounds with zip bomb protection, and loopback remote port forward binding with local shell environment sanitization,
**So that** malicious remote servers and crafted backup archives cannot hijack local clipboards, execute unauthorized control sequences, exhaust terminal heap memory, perform PBKDF2 CPU exhaustion attacks, or inject shared libraries into local shell sessions.

## Acceptance Criteria
1. **Initial Directory Sanitization & Disconnect Port Forward Teardown (`SshConnectionHandler.kt`, `TelnetConnectionHandler.kt`, `BackupSanitizer.kt`):**
   - Strip all `\r`, `\n`, and ASCII control characters (`ch.code < 0x20 || ch.code == 0x7F`) from `initialDirectory` before single-quote escaping in `SshConnectionHandler` and `TelnetConnectionHandler`.
   - Prevent execution of `cd` command if the sanitized `initialDirectory` string is empty or blank.
   - Always invoke `portForwardingOrchestrator.stopAll()` inside `SshConnectionHandler.disconnect()` to guarantee port forward teardown upon session disconnect.
   - Clean imported `initialDirectory` in `BackupSanitizer` using `HostValidator.stripControlChars`.
2. **Gate Remote OSC 52 Clipboard Writes & Harden Terminal Paste (`TerminalViewModel.kt`):**
   - Gate remote OSC 52 clipboard writes behind `allowOsc52Clipboard` and `cossh_settings` preference (`"allow_osc52_clipboard"`), defaulting to disabled in production.
   - Strip raw escape sequences (`\u001b`) from pasted clipboard text in `onPasteTextFromClipboard` to prevent terminal escape injection.
   - Wrap pasted text in bracketed paste escape sequences (`\u001b[200~...\u001b[201~`) when `bracketedPasteEnabled` is true or when DECSET mode 2004 is active on the terminal emulator.
   - Maintain 100% backward compatibility with existing `TerminalViewModelTest` and `TerminalScreenCopyTest`.
3. **Cap Detached Session Output Buffer (`SessionStreamRegistry.kt`):**
   - Track `bufferedBytes` on `ActiveSessionState` and enforce `MAX_DETACHED_BUFFER_BYTES = 2 * 1024 * 1024` (2 MB).
   - In `emitOutput` when UI is detached, evict and zero-fill oldest byte chunks from `outputBuffer` while accumulated size exceeds 2 MB.
   - Slice oversized single data chunks exceeding 2 MB to the most recent 2 MB and zero-fill discarded prefix bytes.
   - Reset `bufferedBytes` to 0 upon UI attachment (`attachUiAndGetBuffer`) and session teardown (`sanitize()`).
4. **Backup PBKDF2 Iteration Bounds & Zip Bomb Protection (`BackupCryptoManager.kt`):**
   - Enforce PBKDF2 iteration bounds: `MIN_PBKDF2_ITERATIONS = 50_000` (or configured test iterations) and `MAX_PBKDF2_ITERATIONS = 1_000_000` for Format v3 backups before invoking `SecretKeyFactory.generateSecret`.
   - Protect against zip bomb decompression attacks by reading `backup.enc` in bounded chunks and throwing `IllegalArgumentException` if the entry exceeds `MAX_BACKUP_ENTRY_BYTES = 20 * 1024 * 1024` (20 MB).
   - Ensure 100% compatibility with existing test suites in `HardenedBackupCryptoTest` and `BackupCryptoManagerTest`.
5. **Local Shell `LD_PRELOAD` Sanitization & Loopback Remote Forward Binding (`LocalShellConnectionHandler.kt`, `PortForwardingOrchestrator.kt`):**
   - Filter out `LD_PRELOAD` and `LD_LIBRARY_PATH` case-insensitively from `profile.envVars` and strip them explicitly after processing environment variables in `LocalShellConnectionHandler`.
   - Bind remote port forwarding requests (`RemotePortForwarder.Forward`) strictly to loopback (`127.0.0.1`) in `PortForwardingOrchestrator` to prevent unintended public interface exposure on remote hosts.
6. **Automated Unit Testing & Zero-Tolerance Quality:**
   - 100% pass rate in `PreReleaseProtocolAndInputHardeningTest.kt` covering all 5 security requirements.
   - Zero compiler warnings, strictly safe typing, and zero regressions across existing test suites.
