# User Story: SSH-224 — SAF Scoped Storage Bridge, Atomic Transfer Staging & Background Transfer Progress Bar

## Epic
**SSH-187**: [EPIC] Power Features — SFTP, Mosh, Automation, Accessibility

## User Story
**As a** mobile user transferring files between my device and a remote server,
**I want** downloads and uploads to interface directly with Android's Storage Access Framework (SAF) using Scoped Storage, with atomic staging, cancellation cleanup, and real-time progress indicators,
**So that** large file transfers complete safely without blocking the UI or leaving partial corrupted files upon network drops.

## Acceptance Criteria
1. **SAF Scoped Storage Bridge (`SftpSafBridge.kt`):**
   - Provide `downloadToSafUri` and `uploadFromSafUri` streaming directly between remote SFTP endpoints and Android `ContentResolver` URIs.
   - Decouple IO operations via `SafIoHandler` interface with default `ContentResolverSafIoHandler` for resilient testability without private Android platform mocks.
2. **Atomic Download Staging & Clean Cancellation:**
   - Stream remote bytes into a hidden cache staging file (`.cossh_part_<uuid>`).
   - Upon 100% completion, stream to destination SAF URI.
   - On transfer failure, coroutine cancellation, or network abort: guarantee immediate cleanup and deletion of partial staging files.
3. **In-App Persistent Transfer Bar (`SftpTransferBanner.kt`):**
   - Expose active transfers via `SftpTransferManager` with progress state flows.
   - Render persistent bottom banner in `SftpBrowserScreen` showing filename, transfer speed (KB/s, MB/s), progress percentage, and an immediate "Cancel" action button.
4. **Automated Test Coverage:**
   - Unit tests in `SftpSafBridgeTest.kt` verifying ContentResolver stream ingestion, atomic staging commit, and cancellation cleanup.
5. **Zero-Tolerance Quality:**
   - Zero compiler warnings, strictly safe typing, no unhandled exceptions.
