# User Story: SSH-253 - Advanced Terminal Execution, Environment Variable Sanitization, Host Certificates & Automation Hardening

**As a security-conscious systems administrator and CoSSH user,**
I want CoSSH to rigorously validate execution environments, sanitize environment variables and directory paths, enforce biometric gating on critical command snippets, validate OpenSSH host certificates against Certificate Authorities, prevent known_hosts MITM poisoning, verify DNSSEC SSHFP fingerprints on the wire, and authenticate pre-connect automation intents,
**so that** hostile local injections, rogue host certificates, tampered DNS records, replayed automation commands, and unauthenticated terminal snippet executions are deterministically blocked.

## Acceptance Criteria

1. **Environment Variable & `initialDirectory` Injection Hardening:**
   - `LocalShellConnectionHandler.sanitizeEnvironment` must strip dangerous environment variables (`LD_PRELOAD`, `LD_LIBRARY_PATH`, `ld_preload`, `Ld_Preload`, etc.) regardless of casing, while preserving valid configuration variables (`APP_ENV=production`, `TERM=xterm-256color`, custom API tokens).
   - `SshConnectionHandler` and `BackupSanitizer` must neutralize directory injection attempts containing control characters (`\r`, `\n`, `\0`, `\u001B`, `0x7F`) and safely escape single quotes to prevent breaking out of `cd '$escapedDir'` shell invocations.

2. **Command Snippets Biometric Gate & Formatting (`TerminalSnippetHandler`):**
   - Command snippets configured with `requireAuth = true` must not dispatch commands immediately to terminal standard input; execution must be held until explicit biometric authentication verification callback succeeds.
   - If biometric authentication is cancelled or fails, no command bytes are emitted.
   - Command snippets configured with `autoSend = true` must format commands with trailing `\r` (carriage return), while `autoSend = false` must emit raw command strings without newline execution.

3. **OpenSSH Host Certificates & `KnownHostsBulkPorter` Anti-MITM Guard:**
   - `OpenSshCertificateValidator` must validate `@cert-authority` signed host certificates: accepting certificates within active temporal validity windows `[validAfter, validBefore]` with matching principals, and rejecting expired certificates, not-yet-valid certificates, principal mismatches, tampered cryptographic signatures, and unrecognized critical options.
   - `KnownHostsBulkPorter` must parse `@cert-authority` and `@revoked` markers, strictly reject lines containing ANSI escape codes or control characters, and abort bulk imports with conflict warnings under `KnownHostsMergeStrategy.STRICT_REJECT_CONFLICTS` when an imported key conflicts with an existing trusted host.

4. **DNSSEC `SSHFP` Adversarial Wire Validation (`SshfpVerifier`):**
   - `SshfpVerifier` must validate DNS binary wire responses: rejecting responses lacking the `AD` (Authenticated Data) bit (`DnssecNotAuthenticated`), rejecting mismatched SHA-256 fingerprints (`FingerprintMismatchAlert`), and accepting authenticated SHA-256 (`fpType = 2`) records matching the host key.

5. **Pre-Connect Automation (`AutomationIntentGuard`, `WolManager`, `PortKnockingManager`):**
   - `AutomationIntentGuard` must cryptographically verify incoming automation intents with constant-time HMAC-SHA256 signatures, rejecting replayed nonces, expired or future timestamps (> 60,000ms skew), tampered signatures, and hostile override extras (`command`, `exec`, `cmd`, `host`, `port`, `password`, `user`).
   - `WolManager` must parse and validate MAC addresses (rejecting malformed strings) and construct standard 102-byte Wake-on-LAN magic packets (`6x 0xFF` followed by 16 repetitions of MAC).
   - `PortKnockingManager` must validate port bounds, rate-limit repeat sequences within a 5-second cooldown window, and handle port knock sequences deterministically.

6. **Zero-Tolerance Quality:**
   - Zero compiler warnings, zero lint issues, strictly safe typing, and 100% test pass rate across all test vectors.
