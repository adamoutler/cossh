# User Story: SSH-251 — Port Forwarding Adversarial Security & Wire Fuzzing Hardening

## Goal
Harden the CoSSH port forwarding subsystem (`PortForwardingOrchestrator`) against adversarial wire exploitation, SSRF/lateral pivoting, malicious protocol fuzzing, header injection, connection flood exhaustion, and abnormal socket terminations under high concurrency. Validate complete adherence to RFC 1928 and RFC 4254 specifications under active attack conditions.

---

## Security Threat Models & Attack Vectors Mitigated

1. **Server-Side Request Forgery (SSRF) & Lateral Network Pivoting:**
   - *Threat:* Malicious actors or compromised local applications leveraging dynamic SOCKS5 (`-D`) or local (`-L`) port forwards to pivot across internal networks, probing cloud metadata endpoints (`169.254.169.254:80`), router administration portals (`192.168.1.1:80`), internal service ports (Telnet `:2323`), wildcard addresses (`0.0.0.0`), or SSH server self-loop amplification (`127.0.0.1:${sshdPort}`).
   - *Mitigation:* Upstream SSH server `TcpForwardingFilter` rejects non-whitelisted destinations (`SSH_MSG_CHANNEL_OPEN_FAILURE`), which `PortForwardingOrchestrator` translates into immediate SOCKS5 error replies (`0x05, 0x01`) or stream teardown on local forwards, without destabilizing the authenticated SSH session.

2. **SOCKS5 Wire Protocol Fuzzing & Malformed Frame Injection:**
   - *Threat:* Protocol fuzzers sending invalid protocol versions (`0x04`, `0x00`, `0xFF`), unsupported commands (`BIND 0x02`, `UDP_ASSOCIATE 0x03`, arbitrary opcode `0x7F`), invalid address types (`0x00`, `0x02`, `0x99`), truncated greeting bytes, or zero-length method negotiation (`nmethods = 0`).
   - *Mitigation:* Strict RFC 1928 error signaling (`COMMAND_NOT_SUPPORTED 0x07`, `ADDRESS_TYPE_NOT_SUPPORTED 0x08`), immediate socket termination on invalid versions/truncated greetings, zero thread leaks, and zero memory leaks.

3. **Domain Name Injection & Host Header Smuggling:**
   - *Threat:* SOCKS5 domain targets (`ATYP = 0x03`) containing null bytes (`127.0.0.1\u0000evil.com`) or CRLF control sequences (`localhost\r\nX-Injected: true`) attempting header injection, C string truncation exploits, or HTTP request smuggling.
   - *Mitigation:* Bounds and character validation rejecting any domain containing bytes `<= '\u001F'` or `'\u007F'`, returning SOCKS5 general failure (`0x05, 0x01`) and terminating the socket while keeping the orchestrator operational.

4. **Connection Flood Exhaustion & Executor Starvation:**
   - *Threat:* Attackers opening concurrent connections up to and beyond system limits to exhaust worker threads and cause Denial of Service (DoS) for legitimate users.
   - *Mitigation:* Strict 32 concurrent forward connection cap (`MAX_CONCURRENT_FORWARD_CONNECTIONS = 32`). Incoming connections beyond 32 are instantly rejected with socket closure (`EOF`). Worker thread pool sized to 32 so active connections do not starve the queue. Once held connections are released, subsequent connections succeed immediately.

5. **Abrupt TCP Reset (RST) & Hard Teardown Under Load:**
   - *Threat:* Abrupt network drops or hostile client resets (`SO_LINGER = 0`) during active streaming leading to stalled copier threads, socket descriptor leaks, or zombie port listeners.
   - *Mitigation:* Complete cleanup in `stopAll()` guaranteeing all `activeClientSockets` and `localServerSockets` are closed and collections emptied.

---

## Technical Implementation Details

- **`PortForwardingOrchestrator.kt`**:
  - Aligned `socksExecutor` thread pool capacity from 16 to `MAX_CONCURRENT_FORWARD_CONNECTIONS` (32) to prevent thread starvation under maximum concurrency.
  - Added null byte and control character validation in domain name parsing (`ATYP = 0x03`), rejecting with RFC 1928 `0x05, 0x01`.
  - Added RFC 1928 `0x05, 0x08` (`ADDRESS_TYPE_NOT_SUPPORTED`) response for invalid address types prior to socket closure.
  - Enforced `numMethods > 0` validation on SOCKS5 greeting frames.
  - Added exception handler on `ChannelFactory.createDirectTCPIPChannel` to emit RFC 1928 `0x05, 0x01` general failure before terminating client socket.
  - Exposed `internal val localServerSockets` for automated lifecycle auditing.

- **`PortForwardingAdversarialSecurityTest.kt`**:
  - Implemented 8 dedicated adversarial security tests with embedded Apache MINA SSH server and embedded HTTP server.
  - 100% test pass rate with zero warnings.

## Acceptance Criteria

1. **SSRF and Pivot Rejection**: Prohibited target attempts via SOCKS5 (`-D`) and Local (`-L`) port forwarding fail gracefully (`0x05, 0x01` or closed stream), while the SSH session remains authenticated and subsequent legitimate requests succeed.
2. **Wire Fuzzing Resilience**: Invalid SOCKS protocol versions (`0x04`, `0x00`, `0xFF`), truncated greetings, and `nmethods = 0` result in immediate EOF socket closure without crashes or leaked sockets.
3. **RFC 1928 Compliance**: Unsupported commands return `[0x05, 0x07, ...]`, unsupported address types return `[0x05, 0x08, ...]`.
4. **Hostile Domain Injection**: Domains with null bytes or control characters are rejected with `0x05, 0x01`, preserving orchestrator functionality.
5. **Connection Cap Enforcement**: 32 concurrent connection limit is strictly enforced; excess connections #33, #34, #35 receive EOF; connection #36 succeeds after release.
6. **Abrupt Reset Recovery**: Sockets closed with `setSoLinger(true, 0)` under active streaming clean up completely; `stopAll()` leaves zero active client or server sockets.
