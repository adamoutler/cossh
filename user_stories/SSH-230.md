# User Story: SSH-230 - Tamper-Evident SHA-256 Hash-Chained Security Audit Log with Keystore Head Anchoring

**As a security auditor and paranoid terminal user,**
I want an immutable, append-only, tamper-evident audit log of all security, session, host key, and authentication events with Keystore head anchoring,
**so that** any post-compromise tampering, line modification, event deletion, or log truncation is immediately flagged and provable.

## Acceptance Criteria
1. **Cryptographic Record Model:** Define `AuditEventType`, `AuditRecord` data class (sequenceNumber, timestampMs, eventType, payload, previousHash, entryHash), and `AuditIntegrityResult` (Valid, Corrupted, EmptyLog).
2. **Append-Only Hash Chaining Engine:** Implement `SecurityAuditLogger.kt` writing to `security_audit/audit_chain.jsonl`.
   - Continuous SHA-256 hash chaining: $H_n = \text{SHA-256}(\text{CanonicalBytes}(R_n, H_{n-1}))$.
   - Deterministic canonical payload formatting with sorted keys.
   - Guaranteed atomic persistence using `FileChannel.force(true)` (`fsync`).
   - Thread and coroutine safety via Kotlin `Mutex`.
   - Complete chain verification detecting single-bit mutation, sequence deletion, reordering, and truncation.
3. **Hardware Keystore Head Anchoring:** Implement `SecurityAuditLogManager.kt` anchoring the terminal head pointer `(lastSequenceNumber, lastHeadHash)` into hardware Keystore-backed `EncryptedSharedPreferences` to defeat file deletion and rollback attacks.
4. **Subsystem Event Wiring:** Instrument critical security boundaries:
   - `SshHandshakeCoordinator.kt`: Session start, authentication success and failure.
   - `TofuHostKeyVerifier` in `SshConnectionManager.kt`: Host key acceptance and rejection.
   - `IdentityStorageManager.kt`: Identity key generation, persistence, and deletion.
   - `AppLockManager.kt`: Biometric app lock configuration, successful unlock, and failed attempts.
5. **Interactive Audit UI:** Create `SecurityAuditLogScreen.kt` accessible via Settings -> App Security & Biometrics:
   - Status banner: "Hash Chain Integrity Verified ✅" vs "TAMPERING DETECTED ⚠️".
   - Severity dots, category filter chips (All, Auth, Sessions, Host Keys, App Lock, Keys).
   - Expandable cryptographic proof details (parent hash, entry hash, payload metadata).
   - JSON-LD and clipboard export capability.
6. **Stress & Adversarial Testing:** Thorough unit tests in `SecurityAuditLoggerTest.kt` verifying 1,000 continuous entries, single-bit payload mutations, sequence deletion, entry reordering, 50 concurrent coroutines under load, and head anchor rollback detection.
