# User Story: SSH-266 — Per-Profile Legacy SSH Crypto Compat Mode, Profile Styling Preservation & Confirmation Friction Modes

## Goal
Provide a per-profile toggle allowing legacy SSH algorithms (SHA-1 KEX, 3DES, Blowfish, CBC ciphers, MD5/SHA-1 MACs) for connecting to older switches, embedded devices, and legacy servers without weakening the global hostile-wire security baseline; eliminate the regression where saving connection profiles reset custom styling (font size, theme, font choice, cursor style, cursor blink); and deliver configurable security friction for Host Key change confirmations (hold-to-confirm vs. explicit overwrite button) and terminal URL opening (`SUSPICIOUS_ONLY`, `ALWAYS`, `NEVER`).

---

## Technical Implementation Details

1. **Hardened & Legacy SSH Configuration (`SecureSshConfig.kt`):**
   - Added `allowLegacyAlgorithms: Boolean = false` constructor parameter to `SecureSshConfig(val allowLegacyAlgorithms: Boolean = false) : AndroidConfig()`.
   - When `allowLegacyAlgorithms == false` (default): strictly purges all weak/deprecated algorithms (`sha1`, `group1-` KEX, `3des`, `blowfish`, `cbc` ciphers, and `sha1`, `md5` MACs) while prepending post-quantum hybrid KEX `Sntrup761X25519KeyExchange.Factory()` at index 0.
   - When `allowLegacyAlgorithms == true`: retains standard `AndroidConfig` legacy algorithms (SHA-1, CBC, 3DES, MD5) while still prepending `Sntrup761X25519KeyExchange.Factory()` at index 0 without duplicates.
   - Wired `SecureSshConfig(allowLegacyAlgorithms = profile.allowLegacyAlgorithms)` in `SshConnectionHandler.kt` and `SshConnectionManager.kt`.

2. **Per-Profile Compatibility Toggle & State Preservation (`ConnectionProfile.kt` & `AddEditProfileViewModel.kt`):**
   - Added `val allowLegacyAlgorithms: Boolean = false` to `ConnectionProfile` data class and updated `equals()` and `hashCode()`.
   - Added `fontSize`, `colorTheme`, `fontChoice`, `cursorStyle`, `cursorBlink`, and `allowLegacyAlgorithms` to `ProfileFormState`.
   - Hydrated these attributes in `loadProfileIfNeeded()` and preserved them in `saveProfileFromState()` and `saveProfile(...)`.
   - Added `"Allow Legacy SSH Algorithms (SHA-1, CBC, 3DES)"` toggle with testTag `"AllowLegacyAlgorithmsSwitch"` under Advanced Configuration in `AddEditProfileScreen.kt`.

3. **Host Key Change Confirmation Friction (`AppNavigation.kt`):**
   - In `HostKeyPromptDialog`, evaluated `SettingsManager(LocalContext.current).isHoldToConfirmHostKeyEnabled`.
   - When `request.isKeyChanged && isHoldToConfirmHostKeyEnabled`, renders high-friction `HoldToConfirmButton` (requiring a 2.5s hold).
   - When `request.isKeyChanged && !isHoldToConfirmHostKeyEnabled`, renders an explicit error-styled button labeled `"Overwrite Host Key"`.

4. **Terminal URL Confirmation Mode Enforcement (`TerminalScreen.kt`):**
   - Enforced `SettingsManager(context).terminalUrlConfirmationMode` upon terminal tap / long press:
     - `ALWAYS`: Always displays the URL confirmation bottom sheet.
     - `NEVER`: Opens the link directly in an external browser activity without prompt.
     - `SUSPICIOUS_ONLY`: Confirms only when URLs are detected as suspicious (`!candidate.isSecure || candidate.isDirectIp || candidate.isPunycode`), bypassing confirmation for trusted standard HTTPS domains.

---

## Acceptance Criteria

1. **Legacy Crypto Suite Isolation:**
   - Default profiles enforce strict suite hardening (no SHA-1, CBC, 3DES, or MD5).
   - Profiles with `allowLegacyAlgorithms = true` retain legacy algorithms while maintaining post-quantum hybrid KEX at index 0.
2. **Profile Styling Integrity:**
   - Editing and saving existing profiles preserves custom font size, color theme, font choice, cursor style, and cursor blink settings.
3. **Host Key Overwrite Friction:**
   - Respects user preference for hold-to-confirm vs. one-tap overwrite button on host key mismatch alerts.
4. **Automated Verification:**
   - 100% test pass in `SecureSshConfigTest` and `AddEditProfileViewModelTest`.
