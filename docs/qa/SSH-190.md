# QA Proof Report: SSH-190 - Scrub DriveSync PII Logging and Enforce IME Incognito / No-Personalized-Learning Flags

## Overview & Threat Model

### 1. DriveSync OAuth PII Leakage
In `DriveSyncManager.kt`, Google ID Token authentication previously logged:
```kotlin
println(("DriveSyncManager").toString() + ": " + ("Auth successful for: ${googleIdTokenCredential.id}").toString())
```
`googleIdTokenCredential.id` contains the user's primary Google email account address. On Android systems, unprivileged processes or log aggregation tools running on the device can inspect system logs in various execution contexts or during debugging. Emitting user email addresses directly to stdout/logcat violates strict data privacy standards and security compliance invariants.

**Remediation:** Sanitized the authentication success message to:
```kotlin
GoogleIdTokenCredential.createFrom(credential.data)
println("DriveSyncManager: Auth successful")
```
The token bundle format remains cryptographically validated by `GoogleIdTokenCredential.createFrom(...)`, but no identity or email PII is emitted to logs.

### 2. Soft Keyboard Predictive Learning of Passwords and Private Keys
Modern Android IMEs (Gboard, SwiftKey, Samsung Keyboard, etc.) train personal dictionaries and predictive machine learning models based on user input unless explicitly instructed otherwise by input method flags:
* **Passwords:** When passwords are typed or made visible in `SecurePasswordEditText`, third-party IMEs may log or suggest previously typed phrases if `IME_FLAG_NO_PERSONALIZED_LEARNING` or `privateImeOptions = "incognito"` are omitted or reset upon input type toggling.
* **Manual PEM Private Keys:** In `AddEditIdentityScreen`, pasting or typing RSA/Ed25519 private keys in PEM format (`-----BEGIN OPENSSH PRIVATE KEY-----`) could be ingested into third-party IME autocomplete dictionaries if the text field is configured with generic text input settings.

**Remediation:**
* In `SecurePasswordEditText.kt`, both `factory` and `update` blocks explicitly enforce:
  ```kotlin
  imeOptions = imeOptions or EditorInfo.IME_FLAG_NO_PERSONALIZED_LEARNING
  privateImeOptions = "incognito"
  ```
  Setting these flags in both blocks ensures that switching visibility between masked (`TYPE_TEXT_VARIATION_PASSWORD`) and unmasked (`TYPE_TEXT_VARIATION_VISIBLE_PASSWORD`) never resets the IME incognito isolation.
* In `AddEditIdentityScreen.kt`, the manual private key input field was updated with:
  ```kotlin
  keyboardOptions = KeyboardOptions(autoCorrect = false, keyboardType = KeyboardType.Password)
  ```
  This signals the IME to disable autocorrect and treat the input area with password-grade privacy isolation.
