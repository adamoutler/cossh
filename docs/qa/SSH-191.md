# Verification Proof for SSH-191: Sanitize Volatile PTY Read Buffers and Close Session Streams on Teardown

## Security Rationale
In accordance with CoSSH's paranoid security architecture regarding volatile state sanitization, sensitive terminal I/O (passwords, private keys, sudo credentials, output text) must not linger in process heap memory once sessions terminate or stream bridge loops exit. Furthermore, dangling open streams prevent clean socket teardown and can cause resource leakage or zombie file descriptors.

## Implementation Summary
1. **`PtyStreamBridge.kt`**:
   - Made the 4KB internal buffer configurable/accessible as an internal property: `internal val buffer: ByteArray = ByteArray(4096)`.
   - Added a strict `finally` block in `startBridge()` executing `buffer.fill(0)` when the loop exits normally, catches an exception, or is interrupted via coroutine cancellation.
2. **`SessionStreamRegistry.kt`**:
   - Added `ActiveSessionState.sanitize()` which drains and zeroes out (`bytes.fill(0)`) all chunks in `outputBuffer` within `synchronized(bufferLock)`.
   - Safely closes `ptyOutputStream` via `try { ptyOutputStream?.close() } catch (_: Exception) {}` and sets `ptyOutputStream = null`.
   - Clears shell references by setting `sshShell = null`.
   - Called `session?.sanitize()` inside `SessionStreamRegistry.clearSession(sessionId)`.
3. **Automated Verification**:
   - Added `PtyStreamBridgeTest.kt` verifying stream forwarding, buffer zeroization on normal completion, buffer zeroization on coroutine cancellation, exception resilience, and default buffer parameter sanitization.
   - Enhanced `SessionStreamRegistryTest.kt` verifying buffer wiping across multiple chunks, stream closure via a tracked stream, stream exception handling, and reference nullification.
