# QA Verification: SSH-212 - RFC 1073 Telnet NAWS Subnegotiation & Loop Guard

## 1. Overview & Scope
Ticket SSH-212 implements RFC 1073 (Telnet Window Size Option - NAWS) subnegotiation in `TelnetConnectionHandler.kt`, accompanied by `TelnetNawsProtocol.kt` enforcing RFC 854 mandatory `0xFF` IAC byte doubling, dimension clamping, and an RFC 1143 Q-method loop suppression state machine. Dynamic window resize events from `TerminalScreen.kt` are routed through `ActiveSessionState.onWindowResize` with 100ms debouncing.

## 2. Hardened Architecture & Security Invariants
- **RFC 1073 Option Code 31**: Registered via Commons Net `WindowSizeOptionHandler(80, 24, true, false, true, false)` and dynamic subnegotiation via `TelnetClient.sendSubnegotiation(...)`.
- **RFC 854 Mandatory IAC Escaping**: Any occurrence of byte 255 (`0xFF`) in the 16-bit width or height must be doubled to `0xFF 0xFF`. Unescaped `0xFF` would desynchronize the Telnet parser state machine and allow remote option injection.
- **Dimension Clamping**: Dimensions are clamped to `[1..65535]` with default fallbacks to `80x24` if non-positive.
- **RFC 1143 Q-Method Loop Guard**: `NawsNegotiationStateMachine` tracks negotiation state (`NO`, `YES`, `WANT_NO`, `WANT_YES`) to suppress duplicate `DO NAWS` frames from triggering repeated `WILL NAWS` responses.
- **Debounced Resize**: `updateWindowSizeWithDebounce(cols, rows, 100L)` coalesces rapid layout changes (such as mobile screen rotation or pinch-to-zoom gestures) into a single remote subnegotiation frame.
