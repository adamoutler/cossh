# SSH-152 QA Proof and Verification: Decouple Validation from AddEditProfileScreen

## User Story
*As a developer and user, I need form validation and parsing logic decoupled from the UI Composable `AddEditProfileScreen` into `AddEditProfileViewModel` so that validation rules (such as port 1..65535 and non-empty host), environment variable parsing, and credential resolution are testable in isolation, consistent across screens, and state-driven.*

## Acceptance Criteria
1. **Decoupled Validation & Parsing**:
   - Environment variables parsing logic extracted from UI Composable to ViewModel (`parseEnvVars`).
   - Port validation enforcing valid ports `1..65535` extracted to ViewModel (`validatePort`).
   - Host validation (non-empty/non-blank) extracted to ViewModel (`validateHost`).
   - Credential resolution (SSH identity override, password bytes encoding, locked password retention, Telnet password auth enforcement) moved to ViewModel (`resolveCredentials`).
   - Protocol switching logic (`setProtocol`) moved to ViewModel.
2. **State-Driven UI**:
   - `AddEditProfileScreen` observes `ProfileFormState`, displaying inline errors (`hostError`, `portError`) via `isError` and `supportingText`.
   - `AddEditProfileScreen` delegates save/validation execution to `viewModel.saveProfile(profileId)` without containing business logic.
3. **Comprehensive Unit Testing**:
   - Unit tests in `AddEditProfileViewModelTest` verifying valid and invalid input handling: invalid ports (0, -1, >65535, non-numeric, empty), valid ports (1, 22, 80, 443, 65535), empty host, valid host, env var parsing, credential resolution, protocol transitions, and save flow validation rejection.

## Architectural Refactoring Summary

### 1. `AddEditProfileViewModel` Enhancements
- Added `hostError: String? = null` and `portError: String? = null` to `ProfileFormState`.
- Introduced `validatePort(port: String): Boolean` checking `port.toIntOrNull() in 1..65535`.
- Introduced `validateHost(host: String): Boolean` checking `host.trim().isNotEmpty()`.
- Introduced `parseEnvVars(envVarsText: String): Map<String, String>` splitting commas, trimming keys and values, preserving values with internal `=` characters, and discarding malformed tokens.
- Introduced `resolveCredentials(state: ProfileFormState): ResolvedCredentials` which encapsulates identity lookups, credential overrides, password byte serialization, and Telnet protocol constraints.
- Introduced `validateForm(state: ProfileFormState): Boolean` updating `_uiState` with `hostError` and `portError`.
- Introduced `saveProfile(profileId: String? = null): Boolean` which runs `validateForm`, builds `ConnectionProfile` using resolved credentials and parsed env vars, saves to `SecurityStorageManager`, resets state on success, and returns `false` on failure without persisting invalid data.
- Introduced `setProtocol(newProto: Protocol)` to encapsulate port default transitions (22 <-> 23) and protocol auth defaults.

### 2. `AddEditProfileScreen` Simplification
- Replaced 46 lines of manual parsing, credential lookup, and password byte array manipulation in `onSave` with a single call:
  ```kotlin
  onSave = {
      if (viewModel.saveProfile(profileId)) {
          onNavigateBack()
      }
  }
  ```
- Delegated protocol switching to `viewModel.setProtocol(newProto)`.
- Connected `hostError` and `portError` from `uiState` to `AddEditProfileScreenContent` and into `OutlinedTextField` `isError` and `supportingText`.
