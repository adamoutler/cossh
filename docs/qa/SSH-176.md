# SSH-176: Implement Command Snippets/Macros

## 1. Architectural Strategy & Security Decisions

### Security & UX Review (Option C Alignment)
During initial testing reality checks, a discrepancy was identified between UI copy ("Requires device unlock to inject") and the actual implementation (which rendered a Compose `AlertDialog` rather than prompting `BiometricPrompt`). Following architectural consultations between the Security Architect, UX Architect, and Testing Architect:
1. **No Security Theater:** The UI copy was updated from "Require Authentication" to **"Require Confirmation"** (*"Requires confirmation dialog before injecting"*), eliminating misleading claims while preserving critical confirmation gating for dangerous commands.
2. **True Biometric Auth Deferred to Epic SSH-182:** Authentic hardware-backed Keystore biometric authorization with `CryptoObject` binding is architecturally scheduled under Epic `SSH-182` ("Optional App Lock & Authentication").
3. **Decoupled Business Logic (`TerminalSnippetHandler`):** Command formatting and confirmation gating logic were decoupled from `TerminalScreen` into a dedicated domain component: [`TerminalSnippetHandler.kt`](file:///home/adamoutler/git/ssh/app/src/main/kotlin/com/adamoutler/ssh/ui/components/TerminalSnippetHandler.kt).
   - Formats UTF-8 bytes and reliably appends `\r` (carriage return) when `autoSend = true`.
   - Formats clean UTF-8 bytes without trailing newlines when `autoSend = false`.
   - Intercepts clicks and routes protected commands (`requireAuth = true`) to user confirmation before dispatching to `sendToTerminal`.

- `testOnSnippetConfirmedDispatchesManualSnippet`: Proves user confirmation dispatches `<command>`.
