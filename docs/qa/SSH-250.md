## 1. User Story

*As a security-focused systems engineer on CoSSH, I want comprehensive and deterministic automated integration test coverage verifying that Local (`-L`), Dynamic SOCKS5 (`-D`), and Remote (`-R`) port forwarding tunnels reliably transport HTTP/1.1 traffic across encrypted SSH channels, maintain byte-for-byte cryptographic integrity across large payloads, cleanly multiplex concurrent shell and tunnel streams without cross-talk, and aggressively clean up all client and server sockets upon termination.*

---

## 2. Implementation Summary

1. **Embedded Apache MINA SshServer Configuration**:
   - Spawns an ephemeral `SshServer` on loopback `127.0.0.1:0` with ephemeral host key provider.
   - Enforces the mock container's HTTP-only forwarding policy via custom `ForwardingFilter`:
     - `canForwardAgent(session, requestType)` -> `false`
     - `canForwardX11(session, requestType)` -> `false`
     - `canListen(address, session)` -> `address.hostName in listOf("127.0.0.1", "localhost")`
     - `canConnect(type, address, session)` -> `address.hostName in listOf("127.0.0.1", "localhost") && address.port == mockHttpServerPort`
   - Configures `ShellFactory` and `CommandFactory` to support concurrent interactive shell sessions and command execution.

2. **Embedded HTTP Server & Endpoints**:
   - Spawns an embedded HTTP server on `127.0.0.1:0` implementing standard endpoints:
     - `GET /` and `GET /status` -> returns `200 OK` with body `"status: ok"`.
     - `POST /echo` -> reads request body, computes SHA-256 digest, sets `X-Payload-Sha256` header, and echoes body with `200 OK`.

3. **Deterministic Integration Tests (`PortForwardingHttpTunnelVerificationTest.kt`)**:
   - `localPortForward_tunnelsHttpGetStatusToBasicHttpServer()`: Configures a `-L` port forward and verifies HTTP `GET /status` returns HTTP 200 and `"status: ok"`.
   - `localPortForward_tunnels32KbHttpPostEchoWithSha256Integrity()`: Sends a deterministic 32,768-byte ASCII payload via `POST /echo` through the local tunnel, asserting exact body match and `X-Payload-Sha256` digest verification.
   - `dynamicSocks5Forward_tunnelsIpv4AndDomainHttpRequestsToBasicHttpServer()`: Performs RFC 1928 SOCKS5 protocol negotiation with IPv4 (`ATYP 0x01`) and Domain Name (`ATYP 0x03`), sending `GET /status` and `POST /echo` over the SOCKS5 tunnel with SHA-256 validation.
   - `multiplexedSessionAndPortForward_concurrentShellAndHttpTunnelsWithoutCrossTalk()`: Opens an interactive shell channel simultaneously with 4 concurrent Local and Dynamic SOCKS5 HTTP requests across a thread pool, verifying zero stream cross-contamination between terminal I/O and HTTP traffic.
   - `remotePortForward_bindsLoopbackAndDeliversReverseHttpRequestAndCleansUpOnStopAll()`: Configures a `-R` reverse tunnel to a local HTTP service, verifies loopback binding on the SSH server, tests reverse HTTP delivery, and confirms `orchestrator.stopAll()` closes 100% of `localServerSockets` and `activeClientSockets`.

4. **Socket Visibility & Cleanup Verification**:
   - Made `localServerSockets` internal in `PortForwardingOrchestrator` to enable direct state inspection during automated tests.
