# Verification Proof for SSH-196: Harden External Intent and Deep-Link Handling via IntentSanitizer

## Security Rationale & Threat Model
In Android applications, `MainActivity` is declared with `android:exported="true"` to serve as the default launcher activity (`android.intent.action.MAIN`). Under Android's IPC model, any third-party application on the device or external intent source can send arbitrary explicit intents to exported activities.

Prior to SSH-196, `AppNavigation.kt` inspected incoming intents and immediately navigated to `terminal?profileId=$profileId&sessionId=$sessionId` if `EXTRA_PROFILE_ID` was present, without:
1. Verifying that the intent action was authenticated (`com.adamoutler.ssh.RESUME_$sessionId`).
2. Validating format or bounds of `profileId` or `sessionId` strings, creating risks of route delimiter injection (e.g. `&param=value`, `#fragment`).
3. Checking if `sessionId` corresponds to an active, authenticated background session in `ConnectionStateRepository.sessions`.
4. Checking if `profileId` exists in encrypted local storage (`SecurityStorageManager.getProfile(profileId)`).
5. Encoding route query parameters via `Uri.encode()`.
6. Consistently clearing `activity.intent` on new intent delivery, creating replay vulnerabilities during activity configuration changes (such as device rotation).
7. Protecting navigation dispatch against unhandled navigation framework exceptions.

`IntentSanitizer` establishes an invariant boundary adhering to the "Walled Component Garden" directive: all external inputs are treated as hostile, whitelisted against strict regexes, cross-checked with active memory and hardware-backed storage, sanitized via URI encoding, and cleared from the activity to prevent replay.

## Implementation Summary

### 1. `IntentSanitizer.kt` (`com.adamoutler.ssh.ui.navigation`)
- **Action Verification**: Confirms `intent.action == "com.adamoutler.ssh.RESUME_$sessionId"`.
- **Regex Format Whitelisting**: Restricts `profileId` and `sessionId` to `^[a-zA-Z0-9_-]{1,64}$`.
- **Active Session Cross-Reference**: Confirms `ConnectionStateRepository.sessions.containsKey(sessionId)`.
- **Stored Profile Validation**: Confirms `SecurityStorageManager.getProfile(profileId) != null`.
- **Route Query URI Encoding**: Encodes parameters in `"terminal?profileId=${Uri.encode(profileId)}&sessionId=${Uri.encode(sessionId)}"`.
- **Replay Protection**: Sets `activity.intent = Intent()` immediately upon receiving any resume intent.
- **Exception Boundary**: Wraps `navController.navigate` in `try / catch` to log and suppress navigation exceptions safely without crashing the UI.

### 2. Integration in `AppNavigation.kt`
- Unified both `DisposableEffect(activity)` (`onNewIntent` listener) and `LaunchedEffect(Unit)` (`activity.intent`) to delegate directly to `IntentSanitizer.sanitizeAndNavigate(intent, navController, activity, securityStorageManager)`.

### 3. Comprehensive Test Suite
- **`IntentSanitizerTest.kt`** (14 unit tests):
  - Valid and invalid identifier regexes (alphanumeric, length boundaries 1-64, rejection of spaces, semicolons, script tags, URL delimiters).
  - Intent detection (`isResumeIntent` for resume actions, extras, and non-resume launcher intents).
  - Null intent, missing extras, empty extras handling.
  - Action mismatch rejection (null action, wrong action, session ID mismatch in action).
  - Active session lookup failure handling.
  - Profile storage lookup failure handling.
  - Successful validation returning verified `SanitizedResumeTarget` with encoded route.
  - Dependency injection lambda overrides (`sessionLookup`, `profileLookup`).
  - Activity intent clearing on invalid resume intents to prevent replay.
  - Navigation exception resilience when `navController.navigate` throws.
- **`AppNavigationCoverageTest.kt`** (12 integration tests):
  - `testAppNavigation_HandlesIntent_SanitizedSuccess`: Verifies authentic resume intent triggers navigation and clears `activity.intent`, plus `onNewIntent` delivery.
  - `testAppNavigation_HandlesIntent_UntrustedRejected`: Verifies forged/untrusted intent without matching action or active session is rejected and `activity.intent` is cleared without navigating.
