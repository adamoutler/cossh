# QA Audit: SSH-241 — Software Supply Chain Security, SLSA v1.0 Provenance & Byte-for-Byte Reproducible Builds

## Epic
**SSH-188**: [EPIC] Security Differentiators — "Most Secure SSH Client on Android"

## Scope of Implementation
1. **Compiler Warning Elimination (`SshfpVerifier.kt` & `PasswordCipher.kt`):**
   - Validated DNS RR class `rrClass == CLASS_IN` and enforced non-blank hostnames in `SshfpVerifier.kt`.
   - Updated `PasswordCipher.kt` to use `setUserAuthenticationParameters(300, ...)` on Android R (API 30+) with `@Suppress("DEPRECATION")` on legacy versions, clearing all warnings in `compileReleaseKotlin`.
2. **SLSA v1.0 & in-toto v1 Provenance Engine (`SupplyChainVerifier.kt`):**
   - Native Kotlin implementation of `https://in-toto.io/Statement/v1` and `https://slsa.dev/provenance/v1`.
   - Generates provenance statements with cryptographic subject digests, builder identity, invocation IDs, build types, parameters, and resolved dependency digests.
   - Validates provenance statements against expected artifact SHA-256 hashes and builder IDs.
   - Computes 64-character lowercase hexadecimal SHA-256 digests for raw byte arrays and files.
3. **Deterministic Archive Reproducibility (`SupplyChainVerifier.kt` & `app/build.gradle.kts`):**
   - Configured Gradle `AbstractArchiveTask` in `app/build.gradle.kts` with `isPreserveFileTimestamps = false` and `isReproducibleFileOrder = true`.
   - Implemented `verifyZipReproducibility` analyzing ZIP/APK streams for strict lexicographical entry ordering and uniform DOS epoch timestamps (within 2-second resolution).
   - Produced structured `ReproducibilityReport` detecting corrupt archives, out-of-order entries, or non-normalized timestamps.
4. **F-Droid Verification Specification (`metadata/com.adamoutler.cobaltssh.yml`):**
   - Created reproducible build blueprint for decentralized verification on independent F-Droid builders.
5. **Architectural Whitepaper:**
   - Appended Section 10 ("Software Supply Chain Security & Reproducible Builds") and updated Section 9 summary matrix in `docs/security-whitepaper.md`.
