# QA Audit: SSH-235 — FIDO2 / WebAuthn Hardware Security Keys (`sk-*`) & Biometric SSH-Agent Forwarding Guard

## Epic
**SSH-188**: [EPIC] Security Differentiators — "Most Secure SSH Client on Android"

## Scope of Implementation
1. **OpenSSH FIDO2 Wire Protocol Parser (`OpenSshFido2WireParser.kt`):**
   - Implemented binary wire serializer and deserializer adhering to OpenSSH `PROTOCOL.u2f`.
   - Supported key types: `sk-ssh-ed25519@openssh.com` and `sk-ecdsa-sha2-nistp256@openssh.com`.
   - Public key blob encoding/decoding (`encodePublicKeyBlob`, `parsePublicKeyBlob`).
   - Wire signature serialization/deserialization (`serializeWireSignature`, `parseWireSignature`).
   - Authenticator signed data blob generator (`buildSignedDataBlob`):
     $$\text{SHA-256}(\text{application}) \parallel \text{flags} \parallel \text{counter} \parallel \text{SHA-256}(\text{message})$$
     producing exactly 69 bytes matching WebAuthn / CTAP2 AuthenticatorData and clientDataHash specifications.
   - ASN.1 DER to OpenSSH wire mpint $(r, s)$ converter (`extractEcdsaRs`, `encodeEcdsaRsToDer`).
   - Flags validation (`validateFlags`) for User Presence (`0x01`) and User Verification (`0x04`).
2. **Hardened Biometric SSH-Agent Handler (`BiometricAuthAgentHandler.kt`):**
   - Implemented full OpenSSH Agent wire protocol message processor:
     - `SSH2_AGENTC_REQUEST_IDENTITIES` (11) -> `SSH2_AGENT_IDENTITIES_ANSWER` (12)
     - `SSH2_AGENTC_SIGN_REQUEST` (13) -> `SSH2_AGENT_SIGN_RESPONSE` (14) or `SSH_AGENT_FAILURE` (5)
   - Enforced per-profile identity whitelisting:
     - If the profile's whitelist of allowed key aliases is empty, exactly 0 keys are reported, preventing unauthorized key enumeration.
     - Unwhitelisted sign requests are immediately denied with `SSH_AGENT_FAILURE`.
   - Enforced per-use biometric confirmation via `BiometricAgentConfirmationBridge`. Any failed or cancelled biometric prompt denies signing.
   - Enforced Forward Loop Guard: `MAX_ALLOWED_HOPS = 1`. Any sign request with hop count $\ge 1$ is immediately rejected with `SSH_AGENT_FAILURE` to eliminate agent forwarding socket hijacking across multi-hop jump hosts.
