# QA Verification Report: SSH-195 - Harden Host-Key Verification Prompting and Enforce Ephemeral Secret Zero-Wiping

## Executive Summary & Security Rationale

In accordance with the **Hostile Wire** and **Volatile State Sanitization** security invariants, CoSSH must defend against two critical vulnerability vectors:
1. **Silent Man-in-the-Middle (MITM) Downgrade & Inaccurate Host-Key Tracking**:
   - Legacy TOFU logic parsed `known_hosts` lines using crude whitespace splitting on the first token, failing when entries contained comma-separated host aliases or non-standard port brackets.
   - Host key fingerprint mismatches were previously computed with conflicting digest algorithms (MD5 vs SHA-256), potentially presenting mismatched fingerprints or mischaracterizing changed keys as new hosts.
   - Non-atomic file writes risked corrupting `known_hosts` during concurrent connections or OS process termination.
   - Dismissing or aborting host-key verification prompts did not deterministically abort the connection handshake with `TransportException(DisconnectReason.HOST_KEY_NOT_VERIFIABLE)`.
2. **Ephemeral Secret Retention in JVM Heap Memory**:
   - When SSH handshakes aborted before authentication (due to host-key mismatch, user prompt cancellation, network timeout, or DNS failure), `profile.password` buffers remained populated in memory indefinitely until garbage collected.
   - In ViewModel lifecycles, user-entered credential arrays (`originalPassword` and `privateKey` in `IdentityViewModel` and `AddEditProfileViewModel`) were discarded without active zero-wiping during `resetState()` and ViewModel teardown (`onCleared()`).

### Remediations Implemented (SSH-195)
- **Hardened `TofuHostKeyVerifier`**:
  - Leverages `OpenSSHKnownHosts` entry parsing with `entry.appliesTo(formattedHost) || (port == 22 && entry.appliesTo(hostname))` for robust alias and custom port (`[host]:port`) matching.
  - Standardizes both `expectedFingerprint` and `receivedFingerprint` on standard OpenSSH `SHA256:<base64>` format.
  - Executes atomic in-place replacements using `Files.move(..., StandardCopyOption.ATOMIC_MOVE, StandardCopyOption.REPLACE_EXISTING)`.
  - Deterministically returns `false` on user abort or dismissal, triggering SSHJ `TransportException(DisconnectReason.HOST_KEY_NOT_VERIFIABLE)` and preventing any unverified connection establishment.
- **Strict Ephemeral Secret Destruction**:
  - `SshHandshakeCoordinator.executeWithConnection`: Enforces `profile.clearSensitiveData()` in a mandatory `finally` block alongside `identity?.clearSensitiveData()`.
  - `SshService.startSshConnection`: Ensures `profile?.clearSensitiveData()` executes in the service coroutine `finally` block on success, failure, and cancellation.
  - `SshConnectionManager.connectAndExecute`: Guarantees `profile.clearSensitiveData()` in `finally`.
  - `IdentityViewModel.kt`: Actively wipes `originalPassword?.fill(0)` and `privateKey?.fill(0)` in `resetState()`, overrides `onCleared() { resetState(); super.onCleared() }`, and zeroes `tempProfile` in `injectPublicKey` finally.
  - `AddEditProfileViewModel.kt`: Actively wipes `originalPassword?.fill(0)` in `resetState()` and overrides `onCleared() { resetState(); super.onCleared() }`.
  - `UserPromptRegistry.kt`: Implements `AutoCloseable` on `AuthCredentials` with `clear() { password?.fill('\u0000') }`.
