# QA Verification Report: SSH-200 - SOCKS5 Listener Hardening & Sensitive Clipboard Protection with Auto-Clear

## Executive Summary & Security Rationale

Under the **Hostile Wire** and **Walled Component Garden** core directives, local background listeners and shared Android OS IPC channels (such as the system clipboard) present substantial attack surfaces:
1. **SOCKS5 Listener Exhaustion Vulnerability:**
   - Previous versions of `PortForwardingOrchestrator` permitted unbounded client socket allocations on local dynamic port forwarding listeners without connection caps.
   - Server sockets had no timeout (`soTimeout = 0`), which could stall listener worker threads upon shutdown or connection stalls.
   - Handshake timeouts were not enforced prior to streaming, leaving listeners vulnerable to slowloris-style handshake stalling attacks.
2. **Persistent Sensitive Clipboard Data Leakage:**
   - Terminal selections copied by users (passwords, tokens, database connection strings, private key snippets) remained in Android's global clipboard indefinitely.
   - On Android 13+ (API 33+), clips lacked the `ClipDescription.EXTRA_IS_SENSITIVE` attribute, causing Android's clipboard preview overlay to display plain credentials on screen and sync them to third-party clipboard services.

### Remediations Implemented (SSH-200)
- **SOCKS5 Listener Hardening (`PortForwardingOrchestrator.kt`):**
   - Enforced `MAX_CONCURRENT_FORWARD_CONNECTIONS = 32`: incoming connections past 32 are immediately rejected and closed.
   - Configured `serverSocket.soTimeout = 5000` (`SERVER_SOCKET_SO_TIMEOUT_MS`) on dynamic listeners to support clean interruption and polling.
   - Enforced `socket.soTimeout = 15_000` (`SOCKS5_HANDSHAKE_TIMEOUT_MS`) during the SOCKS5 handshake phase.
   - Reset client socket to streaming mode upon SSH tunnel initialization: `soTimeout = 0`, `keepAlive = true`, and `tcpNoDelay = true`.
   - Actively tracked client sockets in `ConcurrentHashMap.newKeySet<Socket>()` and cleanly closed all client and server sockets in `stopAll()`.
- **Sensitive Clipboard Manager (`SecureClipboardManager.kt`):**
   - Created `com.adamoutler.ssh.security.SecureClipboardManager`.
   - Applied `ClipDescription.EXTRA_IS_SENSITIVE = true` on API 33+ (Tiramisu).
   - Scheduled a 30-second coroutine auto-clear that clears the clipboard if it still holds the copied text.
   - Automatically cancelled prior auto-clear jobs upon new copy operations.
   - Wired `TerminalViewModel.kt`'s `onCopyTextToClipboard` to `SecureClipboardManager`.
