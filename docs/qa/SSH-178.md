# SSH-178: Optimize Gboard and Soft Keyboard Paste Performance via Micro-Batching

## Overview & Architecture

### Background & Bottleneck
When soft keyboards (such as Gboard, SwiftKey, or Samsung Keyboard) send text during paste, autocorrect completion, or rapid typing, input characters are dispatched one by one into the terminal's input connection. Previously, each character triggered:
1. Synchronous `println` calls on the main/UI thread (`onKeyDown`, `onCodePoint`, `sendToTerminal`), incurring blocking Android `logd` IPC socket calls.
2. In `TerminalScreen.kt`, the coroutine consuming `writeChannel` executed `pty.write(bytes)` followed by `pty.flush()` for every single chunk. In SSH PTY streams, each `flush()` forces SSH channel packetization (`SSH_MSG_CHANNEL_DATA`), encryption, and TCP transmission.

Pasting a 1,000-character payload resulted in 1,000 separate synchronous `logd` IPC writes and 1,000 individual SSH packet flushes, causing perceptible UI jank, thread starvation, and sluggish terminal responsiveness.

### Architecture & Solution

1. **Micro-Batch Channel Draining (`TerminalWriteBatcher`)**:
   - Implemented `TerminalWriteBatcher.processChannel(channel, getOutputStream, maxBatchBytes)` in `app/src/main/kotlin/com/adamoutler/ssh/ui/components/TerminalWriteBatcher.kt`.
   - Suspends on the first byte array via `for (firstBytes in channel)`, ensuring immediate delivery for single keystrokes without artificial delays or polling timers.
   - Once awake, eagerly drains all immediately available queued chunks via non-blocking `channel.tryReceive().getOrNull()` up to a 64 KB safe cap (`DEFAULT_MAX_BATCH_BYTES = 65,536`).
   - Writes all drained byte arrays sequentially under a single monitor lock on `ptyOutputStream` and issues **exactly one** `flush()` call per batch.

2. **Hot-Path Logging IPC Elimination**:
   - Removed synchronous `println` logging from `onKeyDown`, `onCodePoint`, `onExtraKeyPress`, and `sendToTerminal` in `TerminalKeyMapper.kt`.
   - Removed hot-path error printing from the PTY write loop in `TerminalScreen.kt`.

3. **Low-Latency Single Keystroke Preservation**:
   - Zero timer introduced (`delay()` is not used). Single interactive keystrokes suspend and wake immediately, preserving <15ms end-to-end keystroke dispatch latency.
