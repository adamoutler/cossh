# SSH-153 QA Proof and Verification: Segregate ConnectionStateRepository Responsibilities

## User Story
*As a systems architect and developer, I need the `ConnectionStateRepository` god-object segregated into focused domain registries (`SessionStreamRegistry` and `UserPromptRegistry`) so that low-level network byte streams and user interactive prompts are decoupled from high-level connection lifecycle management, eliminating architectural leaks while maintaining backwards compatibility.*

## Acceptance Criteria
1. **Domain Registry Segregation**:
   - `SessionStreamRegistry` encapsulates `ActiveSessionState`, `sessions` map, PTY `OutputStream`, `Shell`, output buffering queues (`attachUiAndGetBuffer`, `detachUi`), and flow emission (`emitOutput`).
   - `UserPromptRegistry` encapsulates `HostKeyPromptRequest`, `AuthPromptRequest`, interactive credential/host key prompt flows, coroutine deferred resolution (`requestPrompt`, `resolvePrompt`, `requestAuthPrompt`, `resolveAuthPrompt`), and state flows (`promptRequest`, `authPromptRequest`).
   - `ConnectionStateRepository` refactored to strictly manage connection lifecycle states (`connectionStates`, `activeConnectionCounts`, `updateConnectionState`, `clearConnectionState`, `addConnection`, `removeConnection`, `clearConnections`).
2. **Backwards Compatibility**:
   - `ConnectionStateRepository` transparently delegates stream and prompt calls to `SessionStreamRegistry` and `UserPromptRegistry`. Existing callers (such as `SshService`, `PasswordAuthenticator`, `SshConnectionManager`, `AppNavigation`, and UI components) operate without regressions.
3. **Dedicated Unit Testing**:
   - `SessionStreamRegistryTest` verifies session creation, session reuse, PTY stream storage, queue buffering when UI is detached, flow emission when UI is attached, UI detachment, and buffer sanitization with zeros on cleanup.
   - `UserPromptRegistryTest` verifies interactive authentication prompts (credentials and cancellation), host key prompts (accept and MITM reject), prompt state flow emissions, test hooks, and deferred cancellation.
   - 100% test pass with zero warnings and zero regressions across existing test suites.

## Architectural Refactoring Summary

### 1. `SessionStreamRegistry.kt`
- Location: `app/src/main/kotlin/com/adamoutler/ssh/network/SessionStreamRegistry.kt`
- Responsibilities:
  - Holds `ActiveSessionState` definition with PTY `OutputStream?`, `Shell?`, `outputBuffer: ConcurrentLinkedQueue<ByteArray>`, and `bufferLock: Any`.
  - Maintains `sessions: ConcurrentHashMap<String, ActiveSessionState>`.
  - Exposes `sessionOutput: SharedFlow<Pair<String, ByteArray>>`.
  - Handles UI buffering lifecycle (`attachUiAndGetBuffer`, `detachUi`).
  - Securely wipes sensitive byte arrays in memory upon `clearSession` or `clearAllSessions`.
  - Manages test mock transcripts (`mockTestTranscripts`) and headless mode flag (`isHeadlessTest`).

### 2. `UserPromptRegistry.kt`
- Location: `app/src/main/kotlin/com/adamoutler/ssh/network/UserPromptRegistry.kt`
- Responsibilities:
  - Holds `HostKeyPromptRequest`, `AuthCredentials`, and `AuthPromptRequest` data structures.
  - Manages `promptRequest: StateFlow<HostKeyPromptRequest?>` and `authPromptRequest: StateFlow<AuthPromptRequest?>`.
  - Suspends and resumes coroutine flows via `CompletableDeferred` (`requestPrompt`, `resolvePrompt`, `requestAuthPrompt`, `resolveAuthPrompt`).
  - Provides `@VisibleForTesting` hooks (`setPromptRequestForTest`, `setAuthPromptRequestForTest`) and `clear()`.

### 3. `ConnectionStateRepository.kt`
- Location: `app/src/main/kotlin/com/adamoutler/ssh/network/ConnectionStateRepository.kt`
- Responsibilities:
  - Focused strictly on connection lifecycle states (`ConnectionState`: Connecting, Connected, Disconnecting, Disconnected, Terminated, Error).
  - Maintains `connectionStates: StateFlow<Map<String, ConnectionState>>` and `activeConnectionCounts: StateFlow<Map<String, Int>>`.
  - Eliminates low-level stream/shell imports (`java.io.OutputStream`, `net.schmizz.sshj.connection.channel.direct.Session.Shell`).
  - Seamlessly routes legacy stream and prompt invocations to `SessionStreamRegistry` and `UserPromptRegistry`.
