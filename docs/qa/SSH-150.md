# QA Verification Proof: SSH-150

## Summary of Changes
Ticket SSH-150: **Extract TerminalInputMapper from TerminalScreen**

Extracted terminal input handling, modifier state management, and ANSI key translation out of `TerminalScreen.kt` into dedicated, cleanly decoupled domain components:

1. **`TerminalModels.kt`**:
   - `TerminalInputState`: Represents the terminal input UI state (`NONE`, `KEYBOARD`, `KEYBOARD_AND_BUTTONS`).
   - `ModifierState`: Tri-state sticky modifier state machine (`INACTIVE` / `UNLATCHED`, `STICKY` / `LATCHED`, `LOCKED`) with `.next()`, `.isActive`, and companion alias getters.

2. **`TerminalKeyMapper.kt`**:
   - Encapsulates key code translation (`KeyEvent` -> ANSI byte sequences).
   - ANSI sequence generation for extra keys (Function keys F1-F12, navigation keys Home/End/PgUp/PgDn/Ins/Del/PrtSc/Pause, arrows, Tab, Esc, Ctrl-C).
   - Ctrl modifier byte calculation across all alphabet characters and control ASCII codes.
   - Alt modifier prepending (`0x1B` ESC) for single-byte inputs.
   - Tri-state sticky modifier lifecycle: one-shot latching (`STICKY` -> `INACTIVE`) vs persistent locks (`LOCKED`).
   - Bleed-through input filtering (`isBleedThroughEvent`) and session disconnection lockout.

3. **`TerminalScreen.kt`**:
   - Refactored `TerminalViewClient` (`onKeyDown`, `onKeyUp`, `readControlKey`, `readAltKey`, `onCodePoint`) and `TerminalExtraKeys` (`onKeyToggle`, `onKeyPress`) to delegate directly to `TerminalKeyMapper`.
