# QA Verification Report: SSH-233 — Fix TerminalRenderer NullPointerException by Enforcing TerminalView Initialization Order

## Overview
- **Ticket ID**: SSH-233
- **Title**: Fix TerminalRenderer NullPointerException by Enforcing TerminalView Initialization Order
- **Status**: Complete & Verified
- **Issue Summary**: On physical Android devices, launching `TerminalScreen` crashed immediately when the `AndroidView` factory in `TerminalScreen.kt` invoked `terminalView.setTypeface(resolvedFont.getTypeface())` before `terminalView.setTextSize(...)`.

---

## Root Cause Analysis
In Termux's `com.termux.view.TerminalView`:
```java
public void setTypeface(Typeface typeface) {
    this.mRenderer = new TerminalRenderer(this.mRenderer.mTextSize, typeface);
    updateSize();
    invalidate();
}
```
`setTypeface()` unconditionally accesses `this.mRenderer.mTextSize`. However, `mRenderer` is only initialized inside `setTextSize(int)`:
```java
public void setTextSize(int textSize) {
    Typeface typeface = (mRenderer == null) ? Typeface.MONOSPACE : mRenderer.mTypeface;
    this.mRenderer = new TerminalRenderer(textSize, typeface);
    updateSize();
}
```
Because `TerminalScreen.kt:590-594` invoked `setTypeface()` before `setTextSize()`, `this.mRenderer` was null, causing:
`java.lang.NullPointerException: Attempt to read from field 'int com.termux.view.TerminalRenderer.mTextSize' on a null object reference in method 'void com.termux.view.TerminalView.setTypeface(android.graphics.Typeface)'`.

---

## Implemented Fix
1. **Reordered Initialization in `TerminalScreen.kt`**:
   - `terminalView.attachSession(session)`
   - `val calculatedTextSize = (currentFontSize * density.density * density.fontScale).toInt().coerceAtLeast(10)`
   - `terminalView.setTextSize(calculatedTextSize)` (creates `mRenderer` safely)
   - `try { terminalView.setTypeface(resolvedFont.getTypeface()) } catch (e: Exception) { AppLog.w(...) }`
   - `resolvedTheme.applyTo(terminalView, session)`
2. **Defensive Error Handling Across Factory and Update**:
   - Hardened both `factory` and `update` composable blocks in `TerminalScreen.kt` with `coerceAtLeast(10)` text size boundaries and defensive try-catch wrappers around `setTypeface()`.
   - Even if font loading or renderer state encounters an issue, the app logs a warning and falls back safely to default system monospace rather than crashing.
