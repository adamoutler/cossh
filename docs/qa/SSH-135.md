# Verification Proof for SSH-135

## Architecture Preflight
Consulted `security-engineer` regarding Android Data Extraction rules. They confirmed that on Android 12+, `android:allowBackup="false"` is ignored for device-to-device transfers, and a `<device-transfer>` block in `data_extraction_rules.xml` is the only way to prevent secrets from moving.

## Artifact 1: `data_extraction_rules.xml`
The following rules have been implemented to explicitly exclude sensitive files from both cloud backups and device transfers:

```xml
<?xml version="1.0" encoding="utf-8"?>
<data-extraction-rules>
    <cloud-backup>
        <exclude domain="sharedpref" path="secret_ssh_profiles.xml" />
        <exclude domain="sharedpref" path="secret_ssh_profiles_fallback.xml" />
        <exclude domain="sharedpref" path="secret_ssh_identities.xml" />
        <exclude domain="sharedpref" path="secret_ssh_identities_fallback.xml" />
        <exclude domain="file" path="ssh_known_hosts" />
        <exclude domain="sharedpref" path="crypto_prefs.xml" />
    </cloud-backup>
    <device-transfer>
        <exclude domain="sharedpref" path="secret_ssh_profiles.xml" />
        <exclude domain="sharedpref" path="secret_ssh_profiles_fallback.xml" />
        <exclude domain="sharedpref" path="secret_ssh_identities.xml" />
        <exclude domain="sharedpref" path="secret_ssh_identities_fallback.xml" />
        <exclude domain="file" path="ssh_known_hosts" />
        <exclude domain="sharedpref" path="crypto_prefs.xml" />
    </device-transfer>
</data-extraction-rules>
```

## Artifact 2: `backup_rules.xml`
The legacy backup rules for Android 11 and below have also been implemented with the same explicit exclusions.
