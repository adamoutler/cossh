# Verification Proof for SSH-257: Volatile Credential Sanitization & Async Identity Save Race Fix

## Summary of Changes
1. **Redundant `@Generated` Annotation Removal (`SSH-255` co-located file ownership):**
   - Removed `@com.adamoutler.ssh.ui.screens.Generated` from `ConnectionListScreen.kt`, `AddEditIdentityScreen.kt`, `IdentityListScreen.kt`, and `InjectKeyDialog.kt`.
   - Deleted obsolete marker file `app/src/main/kotlin/com/adamoutler/ssh/ui/screens/Generated.kt`.
2. **`AddEditProfileViewModel.kt` Sanitization:**
   - Wrapped `storageManager.saveProfile(profile)` in both `saveProfileFromState(id)` and `saveProfile(...)` within `try ... finally` blocks unconditionally calling `profile.clearSensitiveData()` and `resetState()`, ensuring volatile credentials (`profile.password` and `originalPassword`) are zeroed even if storage throws.
3. **`AddEditIdentityScreen.kt` & `IdentityViewModel.kt` Race Fix:**
   - In `AddEditIdentityScreen.kt`, passed defensive copies (`password = passBytes?.copyOf()`, `privateKey = uiState.privateKey?.copyOf()`) to `IdentityProfile` before dispatching `viewModel.saveIdentity(identity)` and `viewModel.resetState()`. This eliminates the race condition where `resetState()` on the main thread zeroed out `uiState.privateKey` while the background coroutine was persisting it.
   - In `IdentityViewModel.saveIdentity()`, wrapped `storageManager.saveIdentity(identityToSave)` in a `try ... finally` block invoking `identityToSave.clearSensitiveData()` and `identity.clearSensitiveData()`.
4. **`BackupManager.kt` & `BackupCryptoManager.kt` Sanitization:**
   - In `BackupManager.kt`, wrapped `exportBackup()` and `importBackup()` in `try ... finally` blocks that call `.forEach { it.clearSensitiveData() }` on all hydrated profile and identity collections upon completion or exception.
   - In `BackupCryptoManager.kt`, added `try ... catch` exception protection in `importProfilesFromZip()` that scrubs decoded profile and identity credentials before rethrowing if an error occurs post-Base64 decoding. Caller's `password: CharArray` is strictly preserved.
5. **Targeted Security Testing:**
   - Implemented `VolatileStateLifecycleSanitizationTest` validating:
     - `testAddEditProfileViewModel_saveProfile_wipesPasswordEvenIfStorageThrows`
     - `testAddEditProfileViewModel_saveProfileFromState_wipesOriginalPasswordAndResetsState`
     - `testAddEditIdentityScreen_defensiveCopies_isolateFromUiStateReset`
     - `testIdentityViewModel_saveIdentity_wipesCredentialsInFinally`
     - `testBackupManager_exportBackup_wipesHydratedProfilesInFinally`
     - `testBackupManager_importBackup_wipesHydratedProfilesInFinallyWhenPersistenceFails`
     - `testBackupCryptoManager_importProfilesFromZip_doesNotWipeCallerPassword`
