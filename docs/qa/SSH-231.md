## Architectural & Cryptographic Implementation
1. **RFC 4252 §5.1 Continuation:**
   - When an SSH server verifies an initial factor (such as an SSH key or certificate) and responds with `SSH_MSG_USERAUTH_FAILURE` where `partial_success = true`, SSHJ updates `client.userAuth.hadPartialSuccess() = true` and populates `client.userAuth.allowedMethods`.
   - `CompositeAuthenticator` intercepts `hadPartialSuccess()`, logging milestone `[MFA]` and handing off control to `MultiFactorContinuationEngine`.
2. **`MultiFactorContinuationEngine`:**
   - Evaluates server's advertised secondary factors (`keyboard-interactive`, `password`).
   - Prioritizes `KeyboardInteractiveAuthenticator` for PAM / TOTP / Duo push verification.
   - Falls back to `PasswordAuthenticator` with `isMfa = true` skipping redundant username input and rendering `"Second-Factor Password / OTP"`.
3. **UI Indicators & Security UX:**
   - `AuthPromptDialog` renders `"Two-Factor Authentication"` title and `"🛡️ Public Key Verified — Second Factor Required"`.
   - `PamAuthDialog` renders chip `"Public Key Verified • Step 2/2"`.
4. **Volatile Memory Sanitization:**
   - Password arrays (`CharArray`, `ByteArray`) are zeroed in `finally` blocks.
