## Scope of Implementation
1. **R8 Full Mode & ProGuard Rules Scoping (`gradle.properties` & `app/proguard-rules.pro`):**
   - Configured `android.enableR8.fullMode=true` in `gradle.properties` to activate aggressive R8 optimization, class merging, and method inlining across release builds.
   - Refactored `@kotlinx.serialization.Serializable` keep rules in `app/proguard-rules.pro` using precise conditional directives (`-if @kotlinx.serialization.Serializable class **`, `<1>$Companion`, and `<1>$$serializer`) instead of broad wildcard `{ *; }` keeps. This preserves serialization synthetic machinery while allowing R8 to aggressively obfuscate domain, security, and cryptographic business methods.
2. **AppLog Stripping & System.out Elimination (`app/proguard-rules.pro` & `network/*`):**
   - Added `-assumenosideeffects class com.adamoutler.ssh.util.AppLog { public static void v(...); public static void d(...); }` ensuring verbose and debug log strings, formatting calls, and cross-references are eliminated from release DEX bytecode.
   - Verified that zero raw `println(...)` calls exist in `SshConnectionManager.kt`, `SshService.kt`, `SshConnectionHandler.kt`, `SshHandshakeCoordinator.kt`, and `PtyStreamBridge.kt`.
3. **NDK Release Symbol Hardening (`app/build.gradle.kts`):**
   - Set release `ndk { debugSymbolLevel = "SYMBOL_TABLE" }` so local C variable names and full DWARF source paths are omitted from release binaries.
4. **Frida-Immune Billing Test Override Guard (`BillingManager.kt`):**
   - Encapsulated `forceCloudSyncEnabledForTest` behind `isTestOverrideAllowed(isDebugBuild, isRobolectricEnv)` which strictly validates `BuildConfig.DEBUG || isRobolectricEnvironment()`.
   - In production release builds outside test environments, `forceCloudSyncEnabledForTest = true` is completely ignored, neutralizing runtime Frida tampering attempts against billing entitlement.
5. **Consolidated Build Hardening (SSH-255 & SSH-256):**
   - Pruned `releaseImplementation(libs.androidx.ui.test.manifest)` to ensure test manifest activities are never packaged into production release APKs.
   - Refactored `signingConfigs.create("release")` fallback block to use `initWith(signingConfigs.getByName("debug"))`.
   - Updated release build type to safely query signing config using `signingConfigs.findByName("release")`.
