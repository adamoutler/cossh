## 1. Defect Root Cause Analysis & Architectural Fixes

### 1.1 Defect 1: Navigation Crash from Settings to Known Hosts
- **Root Cause**: In `AppNavigation.kt`, the `"knownHosts"` route hosts `KnownHostsScreen()`, which initializes `viewModel: KnownHostsViewModel = viewModel()`. Since `KnownHostsViewModel` extends `AndroidViewModel(application)` with default constructor argument `private val knownHostsManager: KnownHostsManager = KnownHostsManager(application)`, Kotlin generated only a two-argument constructor `(Application, KnownHostsManager)` in bytecode. When Android's `AndroidViewModelFactory` used reflection to instantiate via `getConstructor(Application.class)`, it threw `NoSuchMethodException` and crashed the app with `RuntimeException: Cannot create an instance of class com.adamoutler.ssh.ui.screens.KnownHostsViewModel`.
- **Fix**: Annotated `KnownHostsViewModel @JvmOverloads constructor(...)` so the single-parameter `(Application)` constructor is emitted in bytecode. Verified via `testKnownHostsViewModel_reflectionInstantiationByAndroidViewModelFactory`.

### 1.2 Defect 2: Terminal Clipboard Copy Disabled by Default
- **Root Cause**: `SettingsManager.DEFAULT_ALLOW_OSC52_CLIPBOARD` defaulted to `false`, and `TerminalViewModel.allowOsc52Clipboard` defaulted to `isRobolectric` (false on real devices). When copying text or receiving OSC 52 copy commands, `onCopyTextToClipboard` checked `isAllowed`, evaluated to `false`, and silently returned without writing to Android's `ClipboardManager`.
- **Fix**: Set `DEFAULT_ALLOW_OSC52_CLIPBOARD = true` in `SettingsManager`, `allowOsc52Clipboard = true` in `TerminalViewModel`, and aligned `SettingsViewModel` and `SettingsScreen` defaults to `true`.

### 1.3 Defect 3: Long-Press Paste Terminal Reset & Input Flooding
- **Root Cause**: `onPasteTextFromClipboard` wrote the entire pasted text into `ptyOutputStream` in a single unbuffered burst. When pasting multi-line or large text, the burst overwhelmed the remote PTY / SSH channel window buffer (4KB canonical buffer), corrupting line discipline or triggering remote socket disconnections, causing the terminal session to reset.
- **Fix**: Refactored `onPasteTextFromClipboard` to stream pasted bytes in bounded 256-byte micro-chunks with synchronized stream flushing and coroutine pacing (`delay(10L)` between chunks), allowing the remote terminal and line discipline to consume bytes without buffer overrun or reset.
