# QA Verification Report: SSH-251 - Port Forwarding Adversarial Security & Wire Fuzzing Hardening

## Executive Summary & Security Rationale

Under the **Hostile Wire** and **Shift-Left Absolute Mandate** core directives, network-facing port forwarding subsystems must withstand deliberate adversarial attacks, protocol wire fuzzing, SSRF exploitation, and socket descriptor exhaustion attacks. 

Ticket **SSH-251** hardens `PortForwardingOrchestrator` and validates its resilience under 8 adversarial attack vectors:
1. **SSRF and Lateral Network Pivoting**: Prohibited attempts to forward connections to internal/cloud metadata addresses (`169.254.169.254:80`), wildcard endpoints (`0.0.0.0:$httpServerPort`), SSH server loopback amplification (`127.0.0.1:${sshdPort}`), telnet (`:2323`), or LAN routers (`192.168.1.1:80`) are rejected at the SSH transport layer and translated into RFC 1928 general failure responses (`0x05, 0x01`) or stream teardown on Local (`-L`) forwards, without destabilizing the authenticated SSH session.
2. **SOCKS5 Wire Protocol Fuzzing**: Invalid protocol versions (`0x04`, `0x00`, `0xFF`), unsupported commands (`BIND`, `UDP_ASSOCIATE`, `0x7F`), unsupported address types (`0x00`, `0x02`, `0x99`), truncated frames, and zero-method negotiation are handled strictly according to RFC 1928 (`0x05, 0x07` for commands, `0x05, 0x08` for ATYP, immediate EOF socket closure for invalid versions and truncated frames).
3. **Hostile Domain Injection**: SOCKS5 domain targets (`ATYP = 0x03`) containing null bytes (`127.0.0.1\u0000evil.com`) or CRLF sequences (`localhost\r\nX-Injected: true`) are detected and rejected prior to channel creation, emitting `0x05, 0x01` and preserving subsequent legitimate proxying.
4. **Connection Flood Exhaustion**: Enforces `MAX_CONCURRENT_FORWARD_CONNECTIONS = 32`. When 32 sockets are held open, excess connection attempts #33, #34, #35 are immediately rejected with EOF without queuing or stalling the server. After release, connection #36 succeeds seamlessly.
5. **Abrupt TCP Reset (RST) Under Load**: Abrupt client disconnections (`setSoLinger(true, 0)` / RST) during active streaming data transfers clean up without memory or descriptor leaks. `stopAll()` completely evacuates `activeClientSockets` and `localServerSockets` to 0.
