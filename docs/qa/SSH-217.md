# QA Certification Report: SSH-217

**Ticket ID:** `SSH-217`  
**Title:** Deprecate Broken Profile-Level Key Auth in Favor of Unified Identity Profiles  
**Parent Epic:** `SSH-184` ([EPIC] Authentication & Key Management Parity)  
**Status:** Verification Passed  

---

## 1. Executive Summary
Legacy versions of CoSSH contained a non-functional direct `AuthType.KEY` chip in `AddEditProfileScreen.kt` that attempted to select phantom keys from `SecurityStorageManager.getAllKeys()`. This accessed dead code, searched for nonexistent `key_` preferences, and when connected, triggered an uncaught runtime `IllegalArgumentException: Valid KeyPair required for key-based authentication`.

Under `SSH-217`, key management is unified strictly and exclusively under `IdentityProfile` (backed by Android Keystore MasterKey):
1. **SecurityStorageManager Cleanup:** Pruned dead `getAllKeys()` and removed phantom prefix references.
2. **UI Unification (`AddEditProfileScreen.kt` & `AddEditProfileViewModel.kt`):** Unified `AuthType.KEY` under `IdentityProfile` selection via `IdentityDropdown`, displaying `SelectedIdentityCard` with Keystore MasterKey badges, and `EmptyIdentitiesPromptCard` with direct navigation to identity creation when none exist.
3. **Hardened Handshake Resolution (`SshHandshakeCoordinator.kt`):** Refactored `getAuthenticator` to throw clean `UserAuthException` guiding users to select an Identity Profile when key auth is invoked without credentials, eliminating runtime crashes.
