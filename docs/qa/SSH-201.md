# QA Verification Report: SSH-201 - Production Logging Migration, TLS Provider Precedence, Network Security Cleartext Ban & Crash Redaction

## Executive Summary & Security Rationale

Under the **Zero-Tolerance Quality**, **The Hostile Wire**, and **Walled Component Garden** core directives, production code must never leak diagnostic or cryptographic details to uncontrolled outputs or insecure channels:
1. **Raw `println` Diagnostic Leakage:**
   - Diagnostic and error traces output via `println` pollute standard output and bypass Android logcat filtering, log levels, and production stripping.
2. **TLS Security Provider Usurpation:**
   - In `CoSshApplication.kt`, registering `BouncyCastleProvider` at index 1 (`insertProviderAt(BouncyCastleProvider(), 1)`) preempted Android's native TLS provider (`Conscrypt` / `AndroidOpenSSL`), forcing TLS handshakes and certificate validation through BouncyCastle rather than the OS-optimized hardware-backed TLS engine.
3. **Insecure Network Security Configuration:**
   - The application's `network_security_config.xml` previously included a dummy pin-set for `example.com` and lacked an explicit global ban on cleartext HTTP traffic.
4. **Crash Log Sensitive Data Retention:**
   - Crash dumps on disk previously scrubbed IP addresses and PEM blocks, but lacked patterns to redact Bearer/OAuth tokens and parameter password assignments (`password=...`). Crash files also grew unbounded over time without retention limits.

### Remediations Implemented (SSH-201)
- **Eliminated Raw `println` Calls:**
  - Migrated all `println` calls to `AppLog` across `PortForwardingOrchestrator.kt`, `TelnetConnectionHandler.kt`, `SecureCrashHandler.kt`, `MainActivity.kt`, `DriveSyncManager.kt`, and `TerminalViewModel.kt`.
- **Restored Platform TLS Provider Precedence:**
  - Configured `Security.insertProviderAt(BouncyCastleProvider(), 2)` in `CoSshApplication.kt` to ensure Conscrypt/AndroidOpenSSL remains at position 1.
- **Enforced Strict Cleartext Ban:**
  - Removed dummy `example.com` pins from `app/src/main/res/xml/network_security_config.xml` and configured `<base-config cleartextTrafficPermitted="false" />`.
- **Hardened Crash Log Redaction & Retention:**
  - In `SecureCrashHandler.kt`, added regex filters to redact Bearer/OAuth tokens (`[REDACTED_TOKEN]`), access/refresh tokens (`[REDACTED_TOKEN]`), and password parameter assignments (`[REDACTED_PASSWORD]`).
  - Added `pruneOldCrashLogs(crashDir: File)` retaining at most 5 crash log files (`MAX_CRASH_LOGS = 5`) and purging the oldest on each crash.
