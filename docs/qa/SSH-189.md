# QA Verification Report: SSH-189 - Harden SSHJ Algorithm Suite via SecureSshConfig

## Executive Summary & Security Rationale
In accordance with the **Hostile Wire Security Invariant**, CoSSH must assume that any network path is actively monitored and manipulated by hostile actors capable of executing cryptographic downgrade attacks. Legacy SSH implementations often include backward-compatible algorithms that have been rendered cryptographically broken:
- **Logjam / Weak Discrete Log:** Diffie-Hellman Group 1 (768-bit and 1024-bit MODP) and SHA-1 based key exchanges (`diffie-hellman-group1-sha1`, `diffie-hellman-group14-sha1`, `diffie-hellman-group-exchange-sha1`) are vulnerable to state-sponsored precomputation attacks and hash collision exploits.
- **Sweet32 (CVE-2016-2183):** 64-bit block ciphers such as Triple-DES (`3des-cbc`, `3des-ctr`) and Blowfish (`blowfish-cbc`, `blowfish-ctr`) are vulnerable to birthday attacks after capturing approximately 32 GB of ciphertext, enabling session key and plaintext credential recovery.
- **MD5 / SHA-1 Hash Collision Attacks:** Legacy MAC algorithms (`hmac-md5`, `hmac-sha1` and their 96-bit / ETM counterparts) possess known mathematical weaknesses and collision vectors.

`SecureSshConfig` extends `net.schmizz.sshj.AndroidConfig()` to eliminate these algorithms during initialization before any wire handshake or key negotiation occurs.
