# Verification Proof for SSH-203: Biometric App Lock, Verification Token & State Machine

## Overview
Implemented biometric app locking infrastructure in CoSSH, including cryptographic cipher initialization and `CryptoObject` wrapping in `PasswordCipher`, secure 32-byte verification token generation, SHA-256 fingerprinting and storage in `SecurityStorageManager`, persistent user preferences in `SettingsManager`, reactive lifecycle state machine with timeout enforcement in `AppLockManager`, and interactive configuration controls in `SettingsScreen` and `SettingsViewModel`.

## Key Changes
1. **Cryptographic Key Initialization & Biometrics (`PasswordCipher.kt`):**
   - Implemented `initEncryptCipher(): Cipher` and `initDecryptCipher(iv: ByteArray): Cipher` using AES/GCM/NoPadding (256-bit key length, 128-bit authentication tag).
   - Implemented `@RequiresApi(Build.VERSION_CODES.P) wrapCryptoObject(cipher: Cipher): BiometricPrompt.CryptoObject` for framework biometrics integration.
   - Refactored `encrypt` and `decrypt` to route through centralized initialization methods.
   - Preserved deterministic in-memory symmetric AES key reuse during unit test / headless / Robolectric environments (`resetFallbackKeyForTesting()` for test isolation).
2. **Verification Token Storage & Lifecycle (`SecurityStorageManager.kt`):**
   - `setupAppLock(cipher: Cipher)`: generates 32 random bytes via `SecureRandom`, computes a SHA-256 hash digest, encrypts the token using the authenticated cipher, and stores `app_lock_iv`, `app_lock_ciphertext`, and `app_lock_token_sha256` in Base64 encoding. The raw 32-byte secret is securely zero-wiped with `Arrays.fill(token, 0)` in a `finally` block.
   - `verifyAppLockToken(cipher: Cipher): Boolean`: safely decodes Base64 payloads within a `try/catch` block, decrypts the token, hashes with SHA-256, verifies equality with `MessageDigest.isEqual` (constant-time comparison against timing attacks), zero-wipes decrypted memory in `finally`, and returns `true` on match or `false` on any mismatch or decryption exception.
   - Provided `getAppLockIv(): ByteArray?`, `isAppLockConfigured(): Boolean`, and `clearAppLock()`.
   - Updated `getAllProfiles()` to explicitly exclude all keys prefixed with `app_lock_*`.
3. **User Preferences & Timeout Configuration (`SettingsManager.kt`):**
   - Added `isAppLockEnabled: Boolean` (persisted boolean, default `false`).
   - Added `appLockTimeoutSeconds: Int` (persisted integer, default `0` - immediately).
4. **App Lock State Machine & Lifecycle Tracking (`AppLockManager.kt`):**
   - Reactive state management with `isLocked: StateFlow<Boolean>` and `pendingResumeIntent: MutableStateFlow<Intent?>`.
   - `shouldBeLockedInitially()` evaluates configuration and enabled state on cold start.
   - `enableAppLock(cipher: Cipher)` initializes app lock token and sets state to unlocked.
   - `disableAppLock()` clears app lock keys and transitions `isLocked = false`.
   - `unlockWithCipher(cipher: Cipher): Boolean` checks token via `SecurityStorageManager.verifyAppLockToken(cipher)` and transitions `isLocked = false` on success.
   - `onAppBackgrounded()`: immediately locks if `appLockTimeoutSeconds == 0`; otherwise records background timestamp.
   - `onAppForegrounded()`: calculates elapsed duration and locks if elapsed seconds >= `appLockTimeoutSeconds`.
   - Injected pluggable `clock: () -> Long` for deterministic testing.
5. **Interactive UI Configuration (`SettingsScreen.kt` & `SettingsViewModel.kt`):**
   - Added "App Security & Biometrics" card with switch to toggle App Lock.
   - Added `ExposedDropdownMenuBox` to select inactivity timeout: "Immediately" (0s), "After 30 seconds" (30s), "After 1 minute" (60s), and "After 5 minutes" (300s).
