## Ticket: SSH-209 - Implement Isolated Multi-Hop Jump Host (ProxyJump) Architecture
* **User Story:** [SSH-209](file:///home/adamoutler/git/ssh/user_stories/SSH-209.md)

### 1. Architectural & Logic Implementation
* **Native Direct-TCPIP Channel Chaining (`ConnectionProtocolFactory.kt` & `SshConnectionHandler.kt`):**
  - Resolves jump host profile from `SecurityStorageManager`.
  - Authenticates jump host client, opens native SSH direct-tcpip channel `jumpClient.newDirectConnection(targetHost, targetPort)`.
  - Connects target client via tunnel: `targetClient.connectVia(jumpTunnel)`.
  - Cascaded teardown: target disconnect closes direct-tcpip tunnel and disconnects jump client, eliminating leaked file descriptors.
* **Deterministic DAG Cycle Detection (`JumpHostGraphValidator.kt` & `JumpHostSelector.kt`):**
  - Traverses jump host chain with visited set.
  - Detects self-loops (A ➔ A), 2-node cycles (A ➔ B ➔ A), and arbitrary multi-node cycles (A ➔ B ➔ C ➔ A).
  - Renders red error badges and disables cycling options in the UI.
* **Route Breadcrumb Visualization (`JumpHostSelector.kt` & `AddEditProfileScreen.kt`):**
  - Material 3 card showing encrypted route breadcrumbs: `Device ➔ Bastion ➔ Target Host:Port`.
