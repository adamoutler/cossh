# QA Verification Report: SSH-199 - Upgrade Backup Cryptography to Format v3 with 250k PBKDF2 Iterations, AAD Header Binding, and Full Backward Compatibility

## Executive Summary & Cryptographic Rationale

In accordance with the **Volatile State Sanitization** and **Shift-Left Absolute Mandate** core architectural principles, CoSSH's backup subsystem must resist offline brute-force attacks and prevent archive tampering.

### Problem Statement
1. **Low Iteration Workload:** Prior versions utilized 65,536 PBKDF2 iterations, which is inadequate against modern GPU-accelerated dictionary attacks.
2. **Unauthenticated Metadata:** The legacy format (Format v2) did not authenticate archive parameters, allowing potential header manipulation or parameter tampering.
3. **Volatile Secret Retention:** Intermediate plaintext JSON bytes, derived AES keys, salts, and initialization vectors were left in heap memory without deterministic zero-wiping in error or success paths.

### Remediations Implemented (SSH-199)
- **PBKDF2 Hardening:** Elevated PBKDF2WithHmacSHA256 iterations to 250,000 for all newly created backup exports with a 32-byte cryptographically secure salt.
- **Format v3 Self-Describing Binary Header:** Prepend a structured binary header:
  - Magic: `"COSSH"` (5 bytes, ASCII `0x43, 0x4F, 0x53, 0x53, 0x48`)
  - Version: `0x03` (1 byte)
  - Iterations: `250,000` (4 bytes big-endian Int)
  - Salt Length: `32` (1 byte)
  - Salt: 32 random bytes
  - IV Length: `12` (1 byte)
  - IV: 12 random bytes
- **AEAD Authentication Binding:** The complete Format v3 header is bound as Associated Authenticated Data via `cipher.updateAAD(header)` in AES-256-GCM mode. Any bit-flip in the magic, version, iteration count, salt, or IV causes an immediate `AEADBadTagException` prior to plaintext release.
- **100% Backward Compatibility:** If an incoming archive lacks the `"COSSH"` magic prefix, `importProfilesFromZip` cleanly falls back to Format v2 mode (65,536 iterations, 16-byte salt, 12-byte IV, no AAD).
- **Volatile Secret Zero-Wiping:** All intermediate byte arrays (`plainTextBytes`, `secretKeyBytes`, `salt`, `iv`) are zeroed in mandatory `finally` blocks, and `keySpec.clearPassword()` is invoked.
